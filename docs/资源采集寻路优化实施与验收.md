# 资源采集寻路优化：实施与验收记录

基线：2072b18。实施分支：optimization/collection-plan-20261106。原工作区已有未提交的地形/覆盖/界面成果，本次在独立干净工作区实施，不将这些成果混入构建。

## 已实施

1. `plan_path()` 返回兼容 list 的 PlannedPath，附 local_target/reached_local。远处目标的局部终点完成不等于采集完成。
2. 同场景、同目标、同高度带、邻近起点在12秒内累计2次部分结果后，下次请求继续尝试已有搜索档位。仅成功抵达局部目标才直接选定；全部档位只返回部分结果时，排除重复前沿及失败入口，以行走代价加终点剩余距离比较。普通直线仍只搜索一档。
3. 避免升级后马上退档重新靠墙：已找到通路的档位在同目标下最多保留12秒。保留的是搜索配置，不是碰撞数据或输入许可。新请求继续做场景、几何和碰撞检查；目标或场景变化不复用该配置。
4. 规划诊断包含 request_id、尝试次数、部分结果数、是否升级和 reached_local；每个请求最多记一次部分前沿。规划事件不写 ApproachRisks。进展超时与实际按键行走无位移分开，只有后者可新增临时方向风险；不将其标为已确认实体墙。
5. 同轮同点同次尝试累计15秒高度等待后，记录 height_wait_timeout 并进入现有跳过/有限补采流程。人工暂停、进食、维修不计入该等待。短暂高度恢复、重规划不重置累计；正式补采是新的有限尝试。
6. PointRoutes.create_reordered() 仅另存，校验来源SHA256、排列及白名单；特殊资源、重复坐标和非白名单点是锚点，禁止跨锚点换序。保留点位属性，重新编号，并记录新旧映射与点位摘要。候选文件及元数据一次原子发布，不更改选择文件。中断时原路线仍可用。
7. 优化路线使用独立 UUID 命名空间的逐点走法和实走 SQLite 库；读取、写入及归档索引均隔离，不迁移旧记忆。隔离元数据损坏则拒绝载入，禁止回退共享库。复制候选路线生成新的隔离标识。候选点位内容改动须重新生成候选，以保持来源映射可核验。
8. 离线排序工具只使用有向实走成本。旧记忆缺少可靠场景信息，列为L2；缺失边列为L4未知，不设为零。第1点固定，默认比较含末点回到第1点的闭环。采用受限成对交换，最多200点、2000次候选评估，不宣称全局最优。

## 排序分级

- recommended：原序及候选均无未知边，全部为具备场景/实走完成证据的L1，每条至少3个耗时样本，估算改善超过5%。这仍需实机配对确认。
- exploratory：证据不足。已知边耗时仅列小计，有未知边时整轮估算为null。
- rejected：有充分成本数据，但未找到超过门槛的改善。

L1输入要求 schema=route-directed-costs-v1、route_sha256 与原文件字节摘要相符。每条edge含 from/to、正数 seconds 数组、level=L1、scene_verified=true、walk_completed=true。工具校验结构，不自动证明外部提供者的声明；应由可复核的实走数据制作。

## 独立回滚开关

在启动程序的进程环境中设置以下变量为0，重启程序后恢复该项旧行为；默认1：

- HEARTOPIA_PARTIAL_SEARCH：部分结果升级和短期档位保留。
- HEARTOPIA_MOVEMENT_RISK_ONLY：仅实际按键停滞新增方向风险。
- HEARTOPIA_HEIGHT_WAIT_BUDGET：累计高度等待预算。

P5回滚为重新选择原路线；候选文件和其隔离记忆保留供复核，不自动删除。
