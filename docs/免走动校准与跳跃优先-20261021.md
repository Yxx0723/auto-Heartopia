# 方向读取和巡查策略调整

当前原生窗口的 ReadOnlyPosition 提供 movement_basis，读取本地角色自己持有的 PlayerSphereChecker._cameraForward。方向投影到 XZ 平面并归一化，右向量为 (forward.z, -forward.x)。读取验证角色存活、本地归属、检测器类型、Vector3 布局和检测器位置与当前人物的位置关系；不使用角色面向当作 W 的方向，不注入、不写内存。

回放每次控制循环直接更新方向，包括暂停恢复和换工具后。没有有效方向时释放按键、等待刷新，不退回 WASD 试走。旧底层录制回放和不提供方向 API 的测试读取器保留其原有机制；当前窗口的读取器始终提供此 API。此次实机只读连续 20 次成功读取；尚需用户启动回放核对实际移动方向，不能把只读数据可用当作实走效果已经验证。

开启跳跃脱困时，实际停滞先长按空格大跳；通过后继续，未通过则清除局部路径并重新寻路。水域、山壁和高大实心障碍仍参与输入方向检查。寻路计算预算耗尽不等同于物理停滞。

21:17 的橡木记录曾导致前往位置线索，现场没有确认实体。当前只读快照也只有 global-resource-ecs 位置记录、没有真实橡木模型对象。因此 1～12 号房门巡查不再使用这些记录作为中途目标；只在身份和采集标志完整的真实实体出现时转入采集。全图位置记录依然可以在地图上作为未确认线索查看。
