# 界面性能优化（2026-10-22）

本轮处理原生 Tk 窗口卡顿，保留地图资源、个人路线和游戏输入规则。

## 原因与修改

- 场景每次发布新快照，即使内容相同，界面仍重新合并资源、计算多边形边界并构建空间索引。现在分别比较资源、碰撞输入，复用未变化的部分；昆虫、鸟、鱼的位置、对象消失、状态和碰撞变化仍触发对应更新。
- 移动地图原来逐帧检查全部绘图缓存。现在只在几何内容变化后清理过期对象，按可见集合更新隐藏状态；保留既有缩放、平移及离屏缓存规则。
- 雷达原来每 90 毫秒删除重建图形，大尺寸圆弧的更新还使大片画布失效。现在复用 10 个图元，大范围刻度和扫光保持静态，角色附近呼吸环及连接灯每 120 毫秒更新。悬浮信息继续位于上层。
- XYZ 变化只修改文字；边框、单位、刻线在尺寸变化时才重建。
- 拖动、调整尺寸及最小化时跳过界面和雷达绘制，后台继续接收最新读数，恢复后显示最新状态；坐标采样频率保持原值。
- 整窗透明度从 0.97 改为 1，保留 HUD 配色，避免透明窗口合成的额外成本。

## 验证范围

读取已保存的真实场景（3353 个对象、6307 个碰撞），在隐藏的真实 Tk Canvas 上离线回放，每种操作各 36 次。前后采用相同 cProfile 采样，只测 Python/Tcl 绘图命令耗时，不代表游戏帧率或 Windows 呈现延迟。

| 操作 | 修改前中位数 | 修改后中位数 |
| --- | ---: | ---: |
| 移动 | 22.679 ms | 20.961 ms |
| 缩放 | 27.604 ms | 24.265 ms |
| 内容相同的新场景快照 | 148.253 ms | 19.313 ms |
| 雷达更新 | 0.210 ms | 0.045 ms |

36 次雷达更新新建图元从 360 个减为初始化时的 10 个。首次缩小地图、出现大量未绘制物体时仍可能花费较多时间；本次缩放最大一次约 133 ms，不能据此宣称完全无卡顿。

新增回归覆盖相同场景复用索引、动态对象更新/消失、桥面/缓存样式变化、雷达图元不增长且不重复更新大圆弧、拖动/隐藏窗口停止绘制、XYZ 文字增量更新。构建继续核对打包模块与源码一致，并核对已有路线文件哈希。

原理对照通过代理读取官方 [Tk Canvas 文档](https://www.tcl-lang.org/man/tcl9.0/TkCmd/canvas.html) 和 [tcltk/tk 画布实现](https://github.com/tcltk/tk/blob/main/generic/tkCanvas.c)，重点核对 `coords`、`itemconfigure` 及重绘区域处理。未增加地图依赖。
