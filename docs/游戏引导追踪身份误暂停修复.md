# 游戏引导追踪身份误暂停修复

日期：2026-10-29。基线：`4b59edb`。范围只包含追踪身份、同目标坐标更新、重算等待及对应诊断，不修改碰撞规则、采集路线、输入心跳或路径搜索算法。

## 原因与证据

上一轮回放出现 4 次独立的“目标或场景改变”暂停，用户确认未手动切换目标、传送或切场景。旧日志没有保存前后追踪 ID，不能反推四次完全相同的根因。

旧代码用模块上下文一致且目标 XYZ 距离不超过 `COORD_REACH_RADIUS=0.3` 判断同一目标。这个参数是点位到达容差。实际 TrackingPathModule 使用 UInt64 `token` 关联追踪对象，允许相同 token 的位置更新，因此坐标距离不应替代任务身份；不同 token 也可能恰好拥有相同坐标。

相关游戏类型及位置更新语义已通过本地运行时只读检查，程序集和分析文件未纳入仓库。此次没有调用游戏方法、注入或写入游戏内存。

## 最小改造

- NativeGuidanceReader 对 `token` 做 UInt64、非静态、实例边界检查；活动引导必须有非零 ID。前后状态核对包含 ID，读取中途换目标不发布混合快照。
- `tracking_id` 使用规范十进制字符串，保留全部 64 位精度；路线路径摘要仍叫 `path_token`，二者语义分开。
- `scene_context` 关联版本、进程、域和当前 level；原 `context` 额外含模块身份。模块重建但场景和追踪 ID 相同，必须重新读取完整路线，不直接按换场景暂停。
- 同 ID 同场景的目标坐标更新强制刷新完整路线；刷新失败时保持松键及原重试边界，不继续用旧目标行走。没有增加未经校准的坐标距离容差。
- 不同 ID 即使坐标完全相同也暂停；场景变更即使 ID 相同也暂停。ID 缺失或无效不能退回坐标判断。
- 游戏暂时停止显示路径但 ID 仍存在时输出 pending；控制循环松键等待，沿用已有超时。ID 清空且导航已关闭时输出 inactive 并停止跟随。两种分支都核对读取前后状态和归属，不读取旧路径。
- 仅旧的自定义/测试来源完全没有 ID 字段时，保留旧兼容行为。生产读取器不会因 ID 读取失败而静默降级。

## 诊断与能力边界

暂停记录区分 `tracking_id_changed`、`scene_context_changed`、`tracking_identity_unavailable` 和旧来源的坐标变化。详细 events 保存前后追踪 ID、场景/模块上下文摘要、目标坐标及 XZ/Y 差异；不保存裸模块地址。

current level 的身份变化仍保守暂停；程序不会猜测它是否只是同一小镇内部重建。模块重建的自动刷新要求场景和追踪 ID 均已确认。正常健康查询仍沿用原有松键保护，本阶段不处理全部细碎停顿，也不删除失焦、F6/F9 或碰撞停止逻辑。

## 验证

先运行新增专项，旧代码 19 项失败、1 项通过，覆盖同 ID 坐标更新误暂停、同坐标换 ID 漏检、ID 变更撕裂、重算误当取消及格式校验等；之后补充场景、模块、身份缺失和状态/完整读取之间换 ID 的边界。

专项检查涵盖最大 UInt64、字段类型和范围、ID 缺失或非法、真实场景变化、同场景模块重建、完整路线更新失败后的按键释放、pending 自动恢复，以及旧来源兼容。相关回归包括缓存、停止、失焦、跳跃中变更目标和回放工作线程。

源码只读预检已确认当前完整和轻量读取返回一致的非零追踪 ID、场景身份和目标，完整路径含 346 个点；没有发送输入。最终完整默认、冻结包及 EXE 专项预检结果见交付记录。只读和模拟结果不替代真实回放验收。

最终新增专项 30 项、相关回归组合 126 项通过；干净发布候选完整默认套件执行一次，2813 项通过、27 项预期失败、26 条既有警告，另有 2 项子测试通过，约 218.09 秒。冻结包执行针对本次改动的 227 项回归，全部通过；100 个项目模块与候选源码对照一致。静态和暂存差异检查通过，原有 25 个工作文件校验保留。

实际 EXE 使用 `--check-guidance-identity-output` 执行只读专用预检，完整和轻量读取均为 ready，追踪 ID、场景及目标一致，完整路径 343 点。与较早源码预检比较，场景和 ID 相同，目标坐标却移动约 1.91 单位：旧坐标规则会拒绝，新身份规则不判为换目标。这是两次分别有效的只读观察及纯比较，不表示将旧健康许可用于当前行走，也不替代移动回放。
