# 跟随游戏引导：直路方向抖动修复

## 现象和证据

用户确认直路上也左右摆动、反复修正。当前 `direction_keys()` 每轮从八个 WASD 方向选取与目标夹角最小的一项；在相邻方向的 22.5° 边界附近，没有方向切换缓冲。旧实现的三个测试分别复现了正向边界抖动、反向边界抖动和小幅镜头方向噪声带来的反复换键。

这证明了控制算法存在边界抖动，并不证明此前实机摆动全部由它引起：运行日志仅间隔记录输入，缺少逐周期镜头方向与实际移动向量。移动许可到期、场景数据不可用的停顿仍需另行处理。

## 最小改动

- 仅 `GuidanceNavigator` 使用相邻方向迟滞，普通点位回放保持原选择逻辑。
- 新方向角度误差的改善不超过 6° 时，可以继续上一次方向。对正交 WASD，等价于将切换边界向外移动 3°；此数值是工程初始值，不是游戏实测能力。
- 大转弯、反向、明显镜头变化、位置跳变、高度层变化、场景变化、过期、到点和显式脱困调用均不继承旧方向。
- 每次保留方向仍经原 `LocalNavigator.steering_keys()` 检查当前实际短程移动，包含墙体、水域、风险与重复失败入口。原方向不再安全时立即使用原有避障选择，不强行延时保持。
- 核对失败、暂停、松键、停止和导航失效清除临时方向状态；状态只占一个有界记录，不存盘，不是走法记忆。
- 增加累计 `steering_metrics`：`switches`、`holds`、`rejected_holds`。它们表示控制器选择与迟滞结果，不等于人眼看到的转身次数。
- 不延长移动许可、碰撞 TTL，不修改目标与完成条件，不移动游戏镜头。

复用核心检查的兼容改动只有一个可选 `preferred_keys` 参数，默认调用行为不变。原先未提交的坡度、覆盖率及 UI 实验保持；发布索引仅包含独立的本次修改。

## 验证

- 修改前：14 项中 3 失败、11 通过，复现三个边界抖动缺陷。
- 新增专项：27 项，覆盖八个方向边界、镜头噪声、明显转向、新墙/水域、失败入口风险、到点、过期、换场景、高度/位置跳变、脱困隔离、输入释放和普通回放兼容。
- 工作区相关回归：209 项通过。
- 首轮干净完整测试：2933 通过、1 失败、27 预期失败。失败为遗漏新阈值的固定值校验登记，补齐测试数据后复跑。
- 最终干净完整测试：2935 通过、27 预期失败、52 警告、2 子测试通过，196.20 秒。警告包含已有字符串转义和 Tk Variable 析构警告，未在本轮扩展处理。
- 冻结包专项：618 通过；104 个打包模块与候选源码一致。Pyflakes、编译与暂存区差异检查通过。
- 实际 EXE 只读预检：4 批快照均有效，8038 个碰撞体，预准备签名均与标准计算一致；没有发送游戏输入。
- 12 秒、3 单位/秒、22.5°直线路径离线闭环：切换从 238 降至 40，最大横向误差从 0.057 增至 0.172 单位。迟滞有减抖与纠偏幅度的取舍，不能将该结果当成游戏观感验证。

## 实机验收与能力边界

新版不自动启动回放。用户在普通直路手动 F6 测试，比较方向选择次数、迟滞命中、输入空档、轨迹和实际观感；再核对急转弯、水边/墙边仍能及时调整，F9/失焦仍释放按键。

只有八个离散移动方向，无法保证任意角度道路都呈现连续模拟摇杆式轨迹。迟滞减少无效切换，但可能略增单次纠偏幅度，必须观察窄路偏移。离线通过不能当作实机自然行走已验收。
