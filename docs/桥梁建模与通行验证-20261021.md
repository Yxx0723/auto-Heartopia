# 桥梁建模与通行验证

本轮将桥梁显示参考和可通行证据分开接入：7 处命名碰撞模型用于地图显示；用户实际步行核对的一座桥另有连续坐标记录，用于窄通道规划。没有把河流轮廓挖成大矩形，也没有把渲染模型或道路中心线直接认定为导航网格。

## 前置调研

全部网络读取显式使用用户指定的本机代理，没有直连回退。参考 GitHub 上 [Recast Navigation](https://github.com/recastnavigation/recastnavigation) 的 [DetourNavMesh.cpp](https://github.com/recastnavigation/recastnavigation/blob/main/Detour/Source/DetourNavMesh.cpp) 和 Unity 官方 [NavMesh Link 文档](https://docs.unity3d.com/Packages/com.unity.ai.navigation@2.0/manual/NavMeshLink.html)。两者的显式连接机制说明：分离的可行走区域可以由有证据的连接点衔接；连接的存在不等于周围整个区域都可走。

本项目没有接入完整 Recast、没有取得游戏 NavMesh，也没有调用游戏导航 API。本轮只借鉴显式连接的做法，在现有局部 A* 图中加入实走通道的连接点，仍对每条连接、平滑捷径和实际 WASD 方向逐段检查。

## 只读数据

- 7 处场景源实例：`Bridge01_C`、两处 `cm_ste_woodenbridge01`、四处 `cm_object_woodenbridge02` 部件。源实例包含世界位置、旋转、缩放及本地网格边界。
- 每个源实例在本次进程的 cooked PhysX 网格中只有一个符合边界的候选，最大边界误差约 0.00523 单位。导出前再次核对源对象字节、Unity 网格头和 PhysX 网格头未变化。
- 导出 1,199 个朝上且倾斜不超过约 30 度的三角面，仅作为显示参考；包含桥的上表面细节，不能保证每片都是可走桥面。没有将这些三角面或其外包框直接开放成过水路径。
- 这些模型实例不包括用户本轮站立的那座桥。该桥通过单独实走采样校准，不能把其他模型的坐标套给它。

显示与通道均由已校验的 GameAssembly 指纹和当前主地图加载状态控制。代码只保存坐标参考，不保存本轮进程地址；运行时不增加全内存扫描。此核验不代表完成重启或换场景后的实机桥梁验证。

## 本轮实走证据

第一轮 60 秒采样只记录到站定，未覆盖用户移动，因此不能作为过桥轨迹。之后在另一端桥头重新采样，用户确认沿同一座桥普通步行返回、不跳跃、不游泳、不用载具。

返回采样共 3,865 个读数，实际移动集中在约 5 秒内。起点约 `(-97.43178, 15.66404, -141.52466)`，终点约 `(-110.69162, 15.62387, -136.33885)`，端点距离约 14.24 单位。最大相邻采样位移约 0.412 单位；整段高度约 15.610～16.058。剔除站定重复读数后保留 46 个坐标点，保持逐段连续性，没有只连两个桥头。

该桥在原有参考水域中已经留有通行缺口；离线对照中原来的直线路径也可通过。因此本轮不能声称复现并修复了这座桥被水域错误阻挡的故障。新记录补足了地图上的桥梁通道显示，并提供独立于参考轮廓缺口的实走证据；水域误盖窄桥、桥面转弯和缺口断裂等情形使用替身回归验证。

## 规划和限制

- 对步行轨迹使用半径 0.45 的保守操作带；它不是实测桥宽，不表示离轨迹 0.45 单位外必然是水。桥梁宽度仍未测量。
- 水域相交区间通过线段/多边形及胶囊形通道的解析区间覆盖判断。跨越整段水域的部分必须连续受通道支持；不能用两个端点或离散采样漏掉中间的小缺口。
- 实走连接作为 A* 的额外节点和边，解决窄桥没有落到网格中心的问题。普通地图障碍、山壁与受阻探针继续检查；水域许可不能覆盖它们。
- 当前位置与整段桥梁的高度差超过 0.75 单位时不使用该连接，防止桥下位置借用桥面。此值是保守适用范围，不是游戏上下层或坡度的实测界限。因此高拱桥、长坡桥和多层道路仍未解决。
- 物理网格参考使用棕金色绘制在水域上方，纳入保留式绘图缓存。未确认主地图时不继续保留旧模型。地图图层开关不控制回放的障碍检查。
- 不修改用户路线，不启用路线记忆，不自动发送游戏输入。需要用户按 F6 开始实机回放；F9 停止。

## 验证范围

`tests/unit/test_bridge_navigation.py` 覆盖通道双向通行、转弯窄桥、0.0002 单位中间缺口、桥下高度、失效世界、缓存来源、实体障碍不能被覆盖、带旋转镜头的替身回放、图层范围及模型版本门禁。替身回放与用户手动过桥是不同证据，尚未在真实游戏中自动执行过桥回放。

采样和模型导出过程没有修改游戏内存、注入代码或调用目标进程函数。全图桥梁尚未穷尽，其他桥需要独立补充通行证据。

本轮 Windows 离线全量回归 1,553 项通过；桥梁专项 26 项通过。安装后的 EXE 内模块回归 585 项通过，并将其 88 个项目模块与当前源码编译结果逐个比较，一致。打包程序的当前游戏只读检查返回主地图 ready、1,244 片桥梁显示面（含实走通道条带）和 1 条实走连接。

已替换并运行原输出位置的窗口版程序，确认只有一个可见窗口且响应正常。原 13 个点位 JSON 的文件哈希在替换前后保持一致；旧程序留有时间戳备份。程序验证没有启动实际游戏回放，自动过桥仍待用户 F6 实机验证。
