# 动态采集全程证据与背包增量确认

## 缺陷与实际依据

2026-10-24 18:25 萤石采集日志中，第一次按 F 后读数为3；维修结束、第二次按 F 前已变为2。旧逻辑分别比较每次按键前后短窗口，丢失了两次按键之间的变化。用户确认萤石、橡木实际均有采集。

只读核对当前角色 StorageBackpack 及 TableBagitem 名称，溜溜橡木物品 ID 为40006，无瑕萤石为40026；场景资源42001/42002、交互类型401/402不能代替背包编号。单次库存快照不能倒推之前20分钟的净增量。

## 实现

- HarvestEvidence为同一对象的一整次采集保存首次资源状态、首次稳定背包数量、背包所属作用域、对象实体/组件身份及唯一证据编号。多次按键、维修间隔和F6暂停不会重新覆盖基准。
- 场景计数下降、冷却开始和实体消失是辅助观察；仅对应物品在同一归属背包中出现正增量才记录resource_confirmed=true。场景暂不可读时仍可核对背包。
- 首次按键后不能补建缺失的背包基准。对象替换或背包作用域变化使证据失效，禁止比较不同场景、角色、背包。
- 按键结束后保持释放，最多继续核对6秒。未确认的证据保留在本轮巡查列表中，每秒复核一次，最多120秒；不会因为等待再次按F。上述时间是工程上限，未经游戏延迟实测校准。
- 列表限于当轮任务；每类最多3次尝试、2种资源，最多6个证据；退出释放独立只读句柄，不跨进程/日期继承证据。
- 背包遍历复用原食物读取的归属及前后稳定性校验；只读随身背包，包含锁定物品和所有分堆，不读仓库，不扫描名称，不改变进食优先级。
- 回放events.jsonl记录证据及背包前后数量/增量；summary.json按证据编号保存结果，重复报告更新同一条，不重复相加。
- 巡查完成集合仅接受明确的背包确认，原“只有计数减少”的旧回调不再当作确认。保留资源按键次数、真实碰撞及路线点位。

## 边界

正增量证明随身背包数量确实增加，但没有服务器产出事件，不能排除相同时段手工交易、取仓或其他来源获得同名物品。暂停很久或晚于120秒才入包的结果不会被自动追认；不会把未确认解释为没有产出。整个资源过程仍以当前任务“确认至少采到一次”为终止语义，不宣称清空资源全部剩余次数。

本轮只做离线模拟、冻结包测试和只读库存核对，没有自动操作真实游戏，未验证实际采集动画延迟。旧回放没有背包基准，不会伪造历史数量或修改旧日志。

轮询超时采用项目既有单调时钟；参考Python time.monotonic官方文档：https://docs.python.org/3/library/time.html#time.monotonic 。预研另检索GitHub库存增量项目mc-deltautils/InventoryDelta，未引入外部代码或依赖。
