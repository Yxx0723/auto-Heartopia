# 斧镐状态读取失败自动恢复

## 行为

- `read_tool()` 区分 read_failed、incomplete、not_equipped、equipped、locked。读取异常保留真实类型和信息；记录读取起止时间与连续失败数。不完整数据不能通过原有 ToolRepairCycle.usable 检查。
- 已确认锁定立即暂停；已确认未装备使用原自动拿出流程。
- 未确认先释放所有输入，使用已有可中断等待，每隔约 200 ms 重新读取，直接绕过 1 秒检查节流。包含首次失败在内最多连续 5 次，已发生的失败也计入，不重新增加预算。
- 主动重试等待最多四次共约 0.8 秒，另设从本次失败读取开始计的 1.5 秒预算；达到预算不再发起下一次读取。单个同步读取内部不由该外层计时强制打断。
- 成功后清除失败计数并继续当前任务。连续失败则暂停，显示最后一次真实异常；若只有不完整数据则显示结构未确认原因。
- 工具失败提示不再被通用提示转换误改成“角色坐标读取中断”。原始异常也保存在现有回放事件中。

## 采集进度

重试流程不创建、清空或修改 collection，不递增 sent，不扣减 remaining，不发送 F。重试时间不计为行走时间。恢复后原采集流程决定下一次应等待还是发送尚未执行的 F。

F6、F9、窗口失焦沿用原 guard 和可中断等待；无任何重试输入，也不盲点工具或维修盒。

## 修改范围

- utils/flows/coordinate_player.py：工具读取、诊断、有限重试、工具维护的确认入口。
- utils/ui/native_coordinate_monitor.py：只保留工具持续失败提示中的原始异常，不改其他提示。
- tests/unit/test_tool_read_recovery.py：新增恢复与进度测试。
- tests/unit/test_native_coordinate_monitor.py：工具真实错误显示测试。

寻路、碰撞、移动许可、地图系统、点位和路线记忆均不修改。

## 验证

345 项相关源码测试通过，覆盖一次 ValueError 后成功、两次 OSError 后成功、5 次失败暂停、结构不完整、未装备、锁定、已有失败计数、采集中断后不重复 F、多次 F 的剩余进度、F9/F6/失焦，以及原维修、进食与回放回归。打包测试及部署状态见发布记录。

实机验证：若再次短暂读不到工具，应出现“斧镐状态暂未确认，正在重试”，按键保持释放；恢复后继续原点位。持续失败才暂停，事件应包含 tool_read_kind、tool_read_error、tool_last_exception、tool_read_failures 和读取起止时间。
