# 采集路线：逐点设置游戏引导的实现与验收

日期：2026-11-03。基线：`4e14008017abc8cb6d2ae30c1e05ed071318480d`。

## 行为

在原有采集路线启用“自动寻路”时，当前点距离较远就自动打开游戏大地图，为该点创建或复用自定义标记，点击追踪，核对游戏实际目标与完整引导线，再关闭地图并沿原生引导行走。用户仍通过 F6 启动/暂停，F9 停止。

保持原路线顺序、循环、点位 XYZ、每点采集次数和等待规则。原生引导到末端不代表已经到达采集交互范围，更不代表已采到；随后仍执行原来的精确到点及高度检查、采集与等待。已在 1.5 单位精确接近范围内时不再打开地图。引导结束后距点仍超过原有局部搜索半径 32 单位则报错，不自动转为长距离直线。

## 调用链

`PointPlayback._execute` → `CollectionNavigator(native_map_collection=True)` → `drive_points` → `NativeCollectionFollower.before_waypoint_navigation` → `MapTargeter.set_target` → 原 `GuidanceFollower` → 原采集控制器的精确接近、采集和等待。

原来的“跟随游戏引导”入口保留。默认独立引导不交互；新增的可选维护回调仅由采集控制器装配，用于引导行走期间继续检查体力、持用工具和维修。菜单操作前同时撤销内外行走输入许可；维护结束重新核对路线和碰撞后继续。

采集使用独立的导航碰撞供应工作线程，复用现有 `NavigationProcessScene`。资源识别仍使用原场景来源，避免把精简碰撞快照误作资源对象列表。

## 地图读取和设标

1. 仅从当前 UIManager、面板栈中取得唯一的 MapPanel，核对运行域、场景和当前区域。
2. 当前游戏版本的原生 UI 句柄、矩形缓存和父级 TRS 布局由该版本实际 accessor 核对；按模块指纹固定，版本不同拒绝使用。只读，不调用游戏函数、不修改进程内存。
3. 用实际 Canvas、sketch 平移、缩放及 MapRatio 转换坐标。两次视图必须一致且新鲜；不将超出可操作区域的坐标夹到地图边缘。
4. 按用户要求先缩小到当前地图允许的最低比例，读取真实滑块值确认到达最小后再有限平移。每次操作后重新投影，并确认实际平移使目标靠近可操作区域，不能用预计拖动量代替真实读回。
5. 设标准备及平移后发现添加标记、标记详情或重叠标记列表时，点击经过核对的地图空白处收起，不点击弹窗内保存、删除等按钮。本次已经选中并核对正确的追踪详情则保留，继续执行追踪。
6. 读取 MapPanel 当前持有的 `_spotWidgets` 链表。原 MapSystem 初始列表可能漏掉新保存标记，不能用它判断保存失败。核对链表数量、版本、节点互链、组件归属、标记 ID 和布局前后一致性。
7. 自定义标记位置从当前控件 root 的 anchoredPosition / MapRatio 推导。它是二维地图显示位置；返回 Y=0 不代表脚下地面高度。不能用旧 MapSpot._position 代替可能已经编辑过的实时位置。
8. 同坐标附近已有自定义标记则复用。否则长按对应位置，读回“添加标记”的世界 XZ，再按保存。必须识别唯一新增 ID，不能仅凭弹窗关闭判定成功。
9. 点击该位置，核对选中的 ID 和类别，再追踪。如果已经追踪相同目标，不再次点击以免取消追踪。
10. 取得两份新鲜且稳定的原生引导读数，核对场景、追踪 ID、目标 XZ 和路径版本。引导重定向至公交点等其他目标时拒绝行走。行走期间继续绑定本次采集点，换目标或换场景即停止使用旧路线。

## 输入保护

地图鼠标、按键操作复用产品原有输入设备。每次按下前核对前台、窗口尺寸及鼠标实际到达位置；点击按钮前重新读取按钮所属目标及矩形。长按有独立短许可 watchdog，读取阻塞或 F9/失焦时能释放输入，不能由扫描线程无限维持按下。

默认长按 1.1 秒：当前游戏 PC 长按触发为 1 秒，额外 0.1 秒为工程余量。其余默认超时、误差、边距和最多缩放次数为工程保护参数，不是实测角色能力。参数集中于 `map_target_policy.py` 并拒绝非有限数、负数或可能造成忙循环的零等待。

碰撞数据新鲜度、实体及山壁碰撞保护保留。只有原生引导段沿用此前用户选择的忽略近似水域策略；本地精确接近仍采用原采集导航约束。

## 能力边界与试跑

本版不删除用户地图标记，也不自动删除新增标记。同位置可复用，但游戏标记数量上限仍然有效。达到上限、标记被过滤、重叠图标弹出选择列表、有限平移与缩放后仍看不到目标、地图尚未稳定或网络迟延超时，均应停止设标并给出原因；不猜测列表行号，不把未确认目标交给行走。

恢复 F6 时若上次留下未保存的标记编辑，按用户授权点击空白处收起，不保存或猜测其归属；随后重新核对本次点位。未实现跨版本布局、跨区域地图或完整三维楼层设标；平移有次数、时限及可操作区域限制。

首次实机验收应使用桌面原有的短路线、循环 1 次，保持游戏前台，先看自动打开地图、长按、保存、追踪和关闭是否完整，再核对行走、到点按 F 和等待。错误目标、意外入水、持续顶墙或菜单误点时立即 F9，并从日志区分地图操作、引导、碰撞供应和采集阶段；未完成这一步不登记为全程自动采集通过。


## 首次试跑后的地图操作修正（2026-11-03）

13:29 这次回放在启动后约 14.1 秒报“地图操作未确认”，没有进入保存标记和实际引导行走。同期导航碰撞扫描正常，不能把这次错误归为碰撞快照断供。旧日志缺少具体地图操作阶段，无法单凭现有记录确定停在打开、关闭还是缩放。

补充源码核对发现：CommonMapBar 的 OpenMap 快捷键回调执行打开地图，并不能作为 M 双向切换的可靠依据；MapPanel 的标准返回按钮则明确绑定当前面板关闭。程序现改为从当前 UI 栈读取 MapHudPanel → CommonMapBar.map_btn 打开，通过当前 MapPanel → CommonTitleWidget.back_btn 关闭。核对根节点激活、按钮可交互、实际矩形和目标归属；返回按钮必须绑定本面板且没有自定义回调。不会依据旧的池化面板按钮发送输入。

目标超出地图可操作区域时，旧逻辑直接发滚轮，鼠标可能仍在工具窗口或地图控件上。现先把鼠标移到已确认地图区域内，读回实际指针位置后才滚动，并继续核对实际缩放变化；视图变化或指针未到位时不滚动。未延长原有超时，不减少目标、场景或碰撞校验。

每阶段记录 map_stage，超时同时记录 map_observed、map_read_error 和 map_wait_seconds。错误信息区分打开地图、关闭地图、缩放、长按、保存及追踪，避免再次只显示笼统的“地图操作未确认”。

新增离线测试先复现鼠标在地图外无法缩放、M 只能打开而关闭超时两种情况，再验证按钮开关、缩放前定位及阶段错误提示。实际小地图按钮矩形已只读读取成功；整条自动操作仍需要用户在新程序里按 F6 验证。以上不代表已经自动走通采集路线。


## 目标在当前视野上方：自动平移补充（2026-11-03）

用户补充确认：首次试跑已经打开大地图，但当前视野偏下，目标位于上方，需要拖动地图。前述版本只有缩小视图，不具备自动平移，是这类情况的能力缺口。本轮在已经修复的按钮开关及鼠标定位基础上补充以下步骤：

- 从真实 Canvas、sketch、缩放和目标 XZ 算出目标的客户区位置，求目标移向可操作区域中心所需的屏幕位移。目标在上方时，拖动方向是向下，不是反过来移动人物。
- 每次拖动的起点、终点及保守包围矩形位于已确认的地图可操作区域内，不穿越已知界面遮挡。每轴位移限制为区域内跨度的 45%，是工程边界，不是游戏能力数据。
- 默认每次拖动 0.35 秒、分 12 段执行。先核对鼠标到达起点，再按住左键；各段继续核对指针和前台、停止状态，由独立短许可保护输入。任何异常都释放鼠标。
- 放开后读回实际平移。场景、面板身份、画布、缩放或操作区域变化时拒绝复用旧投影。读回方向反而远离目标时停止；无进展时不无限拖动，转为有限缩放。
- 默认最多 12 次平移，沿用原有整次设标 40 秒限制；超时不延长。每次平移成功都重新读取两份视图，只有目标真正进入可操作区域后才长按设标。

离线测试覆盖上下左右四方向、连续多次平移、错误方向、无进展、F9、场景/缩放变化、控件遮挡，以及平移后保存、追踪、核对并关闭地图的完整模拟。未把该模拟视为真实游戏自动设标通过；仍以新版首段实机日志验收。


## 方式 A：先开大地图，再操作鼠标（2026-11-03）

最新两轮报错在打开大地图前的指针检查。用户确认当前为方式 A，游戏内指针隐藏，并要求直接打开大地图后再拖拽，不使用 Alt。原先先点击小地图按钮的顺序要求 HUD 指针可见，与该操作方式不兼容。

当前流程改为：地图未打开时按 M → 读回地图已展开 → 短暂等待界面更新 → 检查鼠标并平移、设标、追踪 → 点击当前地图返回按钮关闭。地图已打开时不再按 M，不把 M 当作关闭开关，不注入 Alt。开图失败不进入鼠标操作；开图后指针仍隐藏或未到位时仍不按下鼠标。F9 中断开图时释放 M。

新增测试先证明旧顺序在指针隐藏时无法启动，再覆盖地图已打开不重按 M、开图失败、F9 释放及开图后继续原设标流程。离线测试不代表本版真实游戏已完成自动设标，仍需 F6 试跑核对。


## 拖动中短许可撤销：有限重新核对（2026-11-03）

21:05 实机日志已经通过开图、校准并进入平移，随后报“地图输入许可已撤销”。用户确认期间始终保持游戏前台，没有暂停、停止或调整窗口。旧日志没有具体撤销原因，因此不能将其描述为已经实机证明的超时。

本轮增加 revocation_reason，明确区分 lease_expired、focus_or_size、pause、stop、watchdog_query_error。地图错误记录 map_revoke_reason 和输入许可指标；修正只持有鼠标、键盘集合为空时释放统计遗漏的问题。输入保护时长和碰撞数据有效期均未改变。

仅在平移阶段捕获 lease_expired：先结束旧许可、确认鼠标已释放，重新读取两份稳定地图数据，核对场景、面板、缩放、操作区域和目标方向，且不能出现标记弹窗。通过后建立新许可并从实际地图位置重新规划，不续按原来的拖动。默认整次设标最多恢复两次，第三次到期停止；仍受原设标总时限和平移次数限制。失焦、暂停、停止、读取异常和其他撤销原因不自动恢复。保存、追踪、长按添加标记不适用此重试，以免重复提交。

离线测试注入控制循环延迟，先复现原实现直接退出，再覆盖一次到期后的重新规划、连续到期上限、非超时撤销、场景变化、反向部分位移、鼠标单独持有时的释放原因，以及重试参数校验。该测试不能代替实际拖动验证，实机仍需检查新的撤销原因和恢复结果。

## 最小缩放优先及空白收起弹窗（2026-11-03）

用户指定顺序为先缩到最小、再平移、弹窗出现时点空白。当前流程取代上文历史记录中的“先平移、无进展再缩小”及“遇旧编辑拒绝继续”策略；历史记录保留作为故障调查依据。

最低比例使用当前面板持有的真实 Slider 的 m_Value/m_MinValue/m_MaxValue 归一化读回确认，不硬编码 0.6，也不以滚轮或按钮无响应推断已到最小。当前使用地图区域滚轮缩小并确认值下降（见下节按钮偏移修正）；最多沿用 24 次缩放及总设标 40 秒的工程限制。最小比例已确认后才平移，目标仍不可操作时明确停止，不无限拖动。

只收起 MapPanel 中已识别的添加标记、标记详情、重叠选择列表。由实际弹窗矩形、当前地图图标矩形及保守地图操作范围排除候选位置，最多尝试三个空白位置，每次读回弹窗是否消失；没有确认空白处或读数变化则不点击。不会点击删除、保存或未知确认按钮。本次长按后的添加面板及已选中正确 ID 的追踪详情是正常任务步骤，不在这些步骤中收起。

放开拖动后先收起可能出现的地图弹窗，再核对平移结果。视图不一致时记录 map_view_changes 中发生变化的字段及前后值，继续保持场景、面板、比例和窗口归属检查，不以放宽比较解决未知原因。

新增离线测试覆盖即使目标已在视野中也先缩到最小、缩放不生效不设标、旧编辑不误保存、弹窗有限重试、空白处避开图标和控件、找不到空白不发送点击，以及拖动新出现弹窗后的收起。只读实机检查已经读到滑块比例及按钮矩形；该检查未发送输入，不能证明自动缩放、弹窗关闭或整条采集路线已通过实机验收。
