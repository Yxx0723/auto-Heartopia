## 阶段 B：有界集合恢复

- 首尾 ActiveHierarchies 读取复用同一预算，从可信根重新取集合，重读前后校验本地角色归属和根。成功空表仍是有效空表。
- 单集合最多两次总尝试；每轮额外尝试最多 8 次，额外耗时 0.1 秒预算只控制新尝试启动，不声称可取消 OS 调用。均为工程预算，未经游戏校准。
- 末尾活跃表核对继续保留，不取消身份、类别、类型、容量等保护；已预检查的活跃表不会再次无保护读取。
- 不对未知引用沿旧指针盲目重试；managed/native 碰撞集合尚不扩大恢复范围，避免没有完整 guard 就承诺局部安全。
- 新增红灯：9 项失败，原阶段 A 3 项通过；另补 3 个真实解码与接线测试。相关回归 331 项通过。
- 完整默认：2445 通过、27 预期失败，另 2 个 subtest 通过，166.28 秒。所选模块 pyflakes 通过。
- 本阶段不改变 worker 关闭与导航策略，下一阶段接入质量门、取消控制及读取器恢复。

## 阶段 C：运行时恢复与导航质量门

- 只有结构化 mutation 且根/本地角色作用域复核通过才保留读取器，失败等待从 0.1 秒递增至最多 2 秒；未知、非法引用、换场景仍关闭重建。成功清零；旧 generation 的迟到错误不能污染新进程的退避计数。
- 实际 MemorySceneMap 绑定 stop/generation 取消控制；注册表重读及实体循环、碰撞边界、发布前检查控制。不宣称能够中断已经执行的底层 OS 调用。
- 快照新增 entities、managed_collisions、native_collisions 完整度与观察区间。未能识别的 owner 可能隐藏 PhysicGroup，故必要 managed 碰撞为 partial，禁止导航。
- navigation_snapshot 统一检查必要碰撞完整度、eligibility、真实观察时间、非有限/未来时间戳。重新发布不能给旧几何续期；没有新字段的旧测试/接口保持原保护语义。
- 原生碰撞失败仍可发布有效实体显示，但导航拒绝。可选矿物/房门失败仍不升级为必要碰撞失败。
- 显示只使用本轮有效结果；partial 实体不进入完整缺失判定或历史保留。未经用户确认不启用旧图标短时保留，场景错误仍可能暂时隐藏资源。
- 复用本地有界日志处理器，轮换大小 256 KiB、备份 2 份，记录阶段、原因、重试数、耗时、必要来源状态，不记录原始异常中的地址或坐标列表。成功摘要约 5 秒一次，错误受有界退避限制。
- 初始 C 红灯 11 项；补充未知 owner、取消、partial 缓存及迟到错误测试。再补 malformed quality 红灯 3 失败/1 通过，修复后最终相关 368 项通过。
- 第一轮完整：2464 通过、27 预期失败，另 2 个 subtest 通过，167.32 秒。对 malformed quality 补强后重新完整回归：2468 通过、27 预期失败，另 2 个 subtest 通过，168.70 秒。
- 冻结包相关回归：709 通过，0 失败；90 个归档模块与候选源码一致。PyInstaller 隔离构建成功，候选 SHA256 为 4ecd59d817f5fcaf0aaa66ee6eb9e2f8a1aed0e817735ff6c8fc88bf1adbe131。
