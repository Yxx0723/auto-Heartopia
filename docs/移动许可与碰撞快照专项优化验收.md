## 许可修复与诊断

1. `CollectionFollower.read()` 在正常移动期间重新读取坐标。此前缩短周期后仍可能命中 50 ms 坐标缓存，从而重复使用同一 position_at；本版不修改时间戳伪装新鲜度，也不在读取时自动续期。
2. 等待周期参考本周期耗时和上一次实际睡眠超时量，提前进入下一轮；预留量仍有 50 ms 上限，并让出至少 1 ms，避免忙循环。不会改变许可截止时间或系统计时器设置。
3. `arm()` 保存 position、guidance、collision、target_distance、input_lease 五个截止条件，实际截止仍取最早者。采集不依赖游戏引导，guidance 为 null。position 的现有 150 ms 上限与 input_lease 的 150 ms 看门狗上限分别记录，collision 的来源观测有效期保持原值。
4. 记录 arm 时间、按键确认时间、两个时刻各自剩余许可、并列限制项及各限制项到期计数。到期释放保留对应的条件记录，不能用新一轮条件覆盖旧到期原因。逐次批准保留最近 32 条记录，余量统计窗口 256 条；累计批准/确认计数不随窗口截断。
5. 原有阶段信息增加累计、最大值与次数，并记录输入锁等待、请求/实际睡眠和超时量；均通过已有事件写出，不新增日志线程或独立日志系统。
6. 普通 `_Follower` 回放流程、到点标准、WASD 碰撞验证和目标距离保护系数不变。单独引导入口只增加五条件记录，原停止规则不变。

## 碰撞供应修复与诊断

1. 已知托管引用失效：独立进程内部关闭并丢弃旧读取器及其元数据、几何与物理读取状态，返回失败，下一请求重新创建读取器；只复用进程和传输通道，减少重复 spawn。
2. 父工作线程仅在确认子进程已丢弃读取器且失败属于既有 fresh-retry 范围时保留通道。失败发布仍立即撤销快照。未知错误、协议错误、进程超时、场景切换等保留原重启/停止流程。
3. SceneMetadata 只缓存同一读取器/域内的已验证字段布局；每个活动对象的类型/归属、引用、启用状态、变换及集合一致性仍重新读取。读取器重建时缓存一起销毁。
4. 不可变几何准备优先处理大量标量坐标，减少重复类型分支；仍完整复制每个可变容器、生成签名，不复用上一批动态几何。
5. SnapshotSupply 新增按原因累计的不可用秒数和无效发布次数。有效快照自然到期记为 expired，显式失败、托管 partial、原生 unavailable 分别归类。原因秒数总和应与不可用总时长一致。
6. 未修改地图刷新、路径重新验证、方向性碰撞、高度/稳定支撑身份、路线及采集点；未启用路线记忆。新快照仍走原有几何比较、地图更新和路径碰撞复核。

## 尚未解决与实机验收

本版没有消除游戏动态集合变更、未知父变换和原生碰撞暂不可用；不将这些数据改判为完整，也不延长 6 s 观测有效期。同步方向读取仍可能阻塞，必须用新版阶段与期限记录确认剩余瓶颈。

1. 原“苹果”6 点、完整回放、循环 1、路线记忆关闭；尽量从基线起点 X≈75.927、Y≈20.803、Z≈93.148 出发，体力和工具状态尽量一致。
2. 保持游戏前台、不手动走动，F6 开始，异常顶墙时 F9；保留失焦及超时释放。
3. 比较完成点数、跳点、卡住次数、总耗时、四类松键、实际批准余量、睡眠分布和供应空档。不同起点或干预不算严格配对。
4. 按 expired_limit_counts 和到期记录确认实际限制项；按 snapshot_unusable_by_reason 分摊供应空档，不重复相加互相重叠的输入等待与数据等待。
5. 至少一轮排查功能回归，稳定收益结论需多轮同条件比较。若完成点数降低或安全事件增加，先回退本次实现，不放宽碰撞或许可。
