## 实现

- 新增纯逻辑 utils/core/special_patrol.py，构建独立的 1→12 号房门巡查任务；不修改用户采集路线。
- 恢复经过旧版测试覆盖的 utils/drivers/house_entrances.py，只读主地图配置。fieldNo 是房号，playerPos 是门前角色站立位置；fieldID 和 pos 不用作房号和门前点。列表必须完整、唯一、类型及世界归属有效。
- utils/drivers/mono_scene.py 将入口配置及其主地图身份发布给现有场景工作线程；身份与流式碰撞列表版本分离。入口读取失败不丢弃原有实体和碰撞数据。
- 新增 utils/flows/special_patrol.py：按号巡查、沿途发现、释放移动键、到点实时确认、复用现有采集与维护流程。
- 巡查使用现有自动寻路和实体、水域、山体碰撞约束；门前被占用时检查邻近候选落脚点，不将参考点本身视为可通行证明。
- 每户观察完成后才计入已巡查；途中发现资源不会丢弃尚未完成的门点。未到达的门点末尾补查一次。
- 当前有效目标优先确认。只认当前场景实时实体，忽略历史缓存和全图位置线索。未确认的候选在本次任务内去重；最多尝试三个候选，防止持续变更候选造成无限循环。
- 有效次数下降才报告确认采到并结束单种任务。消失或冷却仅结束当前按键尝试，不证明掉落；对象实体或组件身份变化时不比较计数宣告成功。
- 场景或小镇身份变化、跨日期时结束任务并要求重新核对；身份或场景持续缺失有等待上限。F6/F9 保留；进食、维修和工具维护等待不作为门点导航超时。
- 在既有 coordinate_player.drive_points 入口分发巡查，窗口层不直接依赖流程层，保持架构检查。PointPlayback 保留原有普通路线行为，并区分巡查未发现、未完成、未确认及确认采到。
- 回放记录保存巡查过程、房号、原因、轨迹及汇总。门前观察不按 F，巡查任务记忆走法关闭，不改变普通路线的记忆偏好。
- 默认连按 F 改为 3 次；工程阈值集中在 thresholds.py，不将其描述为游戏实测加载或采集能力。
