# 萤石与橡木：1—12 号房门巡查需求

日期：2026-10-24

状态：需求草案，待用户审阅；不表示功能已经实现。

范围：无暇萤石、溜溜橡木的发现、确认、采集与巡查恢复。

## 1. 目标与已确认规则

角色不在资源附近时，也能启动巡查，自动前往 1—12 号房门前查找当天资源，而不是因附近未加载资源立即报错。

已确认规则：

1. 巡查目标点设在 **1—12 号房门前**，默认按房号 1→12 依次访问。
2. 房门前是巡查位置，不是资源固定刷新位置，不保证每个房门前都有资源。
3. 移动途中持续读取当前已加载的目标资源；发现后根据有效的实时位置靠近、确认，再采集。
4. 历史资源坐标不能直接代表当天资源坐标，不能把缓存标记当作当前实体。
5. 本轮仅确认需求并编写文档，不修改业务代码，不启动真实游戏操作。

## 2. 任务入口与范围

- 保留“采集萤石”“采集橡木”两种单独任务；点击后若没有当前有效目标，进入房门巡查。
- 若已有有效的当前目标，建议优先确认该目标，避免无意义地先跑到 1 号房。
- 两种资源联合巡查可作为后续选项；本需求不要求立即增加入口或自动修改其他采集路线。
- 启动时检查角色坐标、场景和导航数据；数据不足时说明具体等待原因，避免显示“全图没有资源”。

## 3. 房门巡查点

每个点至少包含：房号、门前接近点 XYZ、所属地图或场景、坐标来源、核验状态，以及核验时间。

- 必须是角色能够站立、靠近的门前位置，避开门框、围栏、墙内、水面及其他障碍。
- 房号与位置一一对应，不按资源历史坐标生成房门点。
- 精确坐标必须由可靠地图数据或实际核验提供。本草案不填写猜测坐标，也不假定现有项目已具备完整的 12 个门前点。
- 缺失或未核验的房门点要单独列出，不得将其计为已完成巡查。
- 这些巡查点独立于用户保存的普通采集路线，不覆盖、重排或删除用户点位。

## 4. 巡查流程

1. 从角色当前位置启动，读取当前场景及有效资源。
2. 若没有可确认的目标，从 1 号房开始，按房号访问门前点。
3. 在前往房门的沿途及抵达后，继续读取资源；抵达后留出可配置的短暂确认时间，等待附近对象加载。
4. 发现所选资源后，暂挂房门巡查，记录尚未完成的房门，进入目标接近流程。
5. 以资源当前坐标选择可通行的交互位置，避免直接把实体中心当作站立点。
6. 到达交互范围后再次确认目标身份、位置和场景有效性，准备工具并采集。
7. 核对采集结果，按任务完成规则决定结束，或返回尚未完成的房门巡查。
8. 完成一轮后汇总已巡查、未完成、已发现和采集结果；不默认无限循环。

房门之间通过现有寻路机制移动。“按房号巡查”规定目标访问顺序，不要求角色沿直线穿过河道、山体或建筑。

## 5. 资源发现与到点确认

| 数据情况 | 允许的用途 | 禁止的解释 |
| --- | --- | --- |
| 当前场景实时有效实体 | 导航接近、到点复核、采集候选 | 仅凭距离接近就宣告采集成功 |
| 同一任务中先前发现、目前未加载的坐标 | 临时候选位置，返回后重新确认 | 远处仍存在、仍未采集 |
| 当天缓存 | 标注来源，辅助返回确认 | 未确认就直接按 F |
| 历史日期或其他场景缓存 | 历史参考，不进入当前实时目标集合 | 当天固定刷新位置 |
| 当前列表没有目标 | 继续巡查或等待必要数据 | 全图不存在、已经采完 |

- “当前有效”须检查场景归属、资源类型及读取时效，不能只检查旧内存地址仍然可读。
- 到点目标消失、类型不符或坐标异常时，停止对该候选的采集操作，重新读取；必要时恢复房门巡查。
- 当前读取器无法覆盖未加载区域；本功能通过移动发现资源，不宣称实现全图实时读取。
- 日期边界、实例或小镇切换规则需实施前核实；不能仅以日期相同就认为是同一份当天资源数据。

## 6. 采集与完成判定

- 使用现有手持斧镐、体力及耐久维护流程，保留现有暂停和停止入口。
- 采集操作为连续按 F，次数沿用任务配置；具体次数不是资源已采完的证据。
- 优先使用可靠的掉落、背包增量、交互反馈或资源状态变化核对结果；可用信号需以实际代码和实机验证为准。
- 不能仅凭“按完 F”或“资源不在列表里”显示“采集完成”。无法可靠确认时记录“已尝试，结果未确认”。
- 结果未确认时采用有限重试及去重保护，避免无限按键，也避免反复采集同一候选。次数和等待时长在实施阶段集中配置，不宣称为游戏实测值。

## 7. 异常、暂停与恢复

| 情况 | 处理要求 |
| --- | --- |
| 某个房门无法到达 | 按现有导航策略尝试恢复，仍失败则记录原因并跳过；一轮后有限补查 |
| 尚未抵达房门就发现资源 | 暂挂当前门点，先确认资源；恢复时不遗漏未完成门点 |
| 人物或场景数据暂时不可用 | 释放移动键，等待并重新检查；超时后给出可操作提示，不无限静默等待 |
| 明确切换地图、小镇或资源实例 | 旧目标及当前巡查进度失效，重新核对房门数据；不得沿旧坐标继续操作 |
| 用户暂停后继续 | 先重读场景、人物及候选目标，再恢复当前任务 |
| 用户停止 | 立即释放按键并结束自动操作，保存本次记录 |
| 一轮未发现目标 | 显示“本轮未发现”，列出未完成门点；允许重试，不显示“全图没有” |
| 只执行了按键、无法确认产出 | 显示结果未确认，不计为确认采集成功 |

单次候选失败不能永久封锁路径，也不能将相反方向或其他高度层自动记为障碍。

## 8. 窗口反馈与任务记录

窗口只显示简明进度，例如：

- “橡木巡查 · 3/12 号房 · 前往门前”
- “发现橡木 · 前往确认”
- “目标暂未加载 · 返回候选位置确认”
- “本轮未发现 · 已巡查 10/12，2 处未完成”
- “已执行采集 · 结果未确认”

每次任务写入现有回放记录体系，至少记录：任务类型、开始与结束时间、场景、房门访问顺序与结果、候选来源及发现时间、目标确认与失效、实际行走轨迹、碰撞及无法通行位置、采集尝试、结果确认和任务结束原因。

暂停、维护、加载等待与采集等待应与有效行走耗时区分。记录供复盘使用，不因此自动启用新的走法记忆或改变用户现有偏好。

## 9. 验收场景

1. 离橡木较远、当前资源未加载时，能开始房门巡查，不直接报“附近未加载”并拒绝启动。
2. 没发现资源时，按 1→12 号房访问，房门点缺失或不可达有独立记录。
3. 沿途发现目标，能接近并重新确认，不必先完成全部 12 个门点。
4. 历史橡木坐标仍有地图标记，但当前位置无实体时，不误采、不宣告成功。
5. 当前目标走远后卸载，能区分候选缓存与实时目标；返回后重新确认。
6. 隔河、山壁或围栏影响房门和目标接近时，继续使用现有碰撞约束，不直线穿障。
7. 未确认掉落时，不把连续按 F 完成作为采集成功。
8. 中途 F6 暂停、F9 停止有效，恢复前重新校验当前场景。
9. 场景切换后不误用旧候选和巡查进度，用户路线及点位保持不变。
10. 一轮无发现、部分门点未巡查及结果未确认，三者在窗口和日志中明确区分。

离线测试仅验证流程及数据语义；门前坐标、实际加载覆盖范围、交互距离和采集反馈必须另做实机核验，不能由模拟测试替代。

## 10. 实施前待核实与建议默认值

以下是建议，尚未全部由用户确认：

- 单种资源任务：确认一次采集成功后结束；若希望当天采尽，应另行明确可靠的完成状态与重复采集规则。
- 完成一轮未找到：结束本轮并保留记录，由用户选择再巡查；不无限自动循环。
- 未到达房门：本轮末尾最多补查一次，避免卡在单点。
- 两种资源联合巡查：后续另加选项，不在单种任务中擅自采集另一种资源。

实施前还需核对：12 个房门坐标来源与核验状态、现有单种采集入口调用链、可靠资源身份与采集结果信号、场景及日期失效机制、数据等待上限。
