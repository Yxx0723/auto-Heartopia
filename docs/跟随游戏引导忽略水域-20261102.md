# 跟随游戏引导：独立水域策略

按用户要求，跟随游戏当前引导时不以水域轮廓拒绝通行，不再实施局部浅水采样方案。此策略不判断水深，不声称水域已经验证为可步行区域。

## 范围

- 产品入口 `PointPlayback._execute_guidance()` 为默认的 `GuidanceNavigator` 显式传入 `respect_water=False`。
- 普通采集路线、`LocalNavigator` 和库调用的默认策略不变；注入的第三方测试/自定义工厂不增加强制参数。
- 水域多边形及其安全边距不加入该模式的硬障碍，水面参考网格的水域绕行代价也不加入。
- 桥梁识别仍使用原水域数据，避免以清空全部水域输入的方式破坏支撑面识别。
- 实体碰撞、山壁、护栏、非水域参考模型代价、失败入口风险继续检查；脱困使用同一水域策略并保留原有山壁检查。
- 原地图绘制数据不修改，水域继续显示。方向减抖、移动许可、场景时效、换目标、失焦、暂停和 F9 保护不调整。
- 策略仅在导航器构造时确定，公共属性只读，避免缓存中的旧地图与新策略不一致。日志 `navigation_timings.respect_water` 可核对实际策略。
- 不修改用户保存路线和点位，不自动操作人物，不启用额外走法记忆。

## 代码路径

`PointPlayback._execute_guidance → GuidanceNavigator → LocalNavigator._build_map / recovery_keys → ObstacleMap → ReferenceRisks`

`ObstacleMap` 只跳过水域多边形候选；实际碰撞体候选与桥梁识别不变。`ReferenceRisks` 只跳过 `water` 图层，其余图层照常构建。A*、路径简化、局部前瞻与实际 WASD 短程检查继续使用同一地图。

## 离线验证与实机边界

新增测试先复现 X≈174.46、Z≈41.25 附近被水域拒绝的案例，以及水面参考代价仍触发绕行的问题；保留普通回放避水、实际实体阻挡、桥梁、恢复路径、场景失效与工厂兼容测试。实际执行结果：修改前 5 项失败、8 项通过；新增专项最终 20 项通过，干净候选相关回归合计 210 项通过。完整默认测试 2955 项通过、27 项预期失败、26 条现有转义警告、2 项子测试通过，209.01 秒；冻结包 664 项通过，104 个模块与候选源码一致。Pyflakes、编译及暂存差异检查通过。实际 EXE 只读预检取得 4 批有效快照，无游戏输入；尚未进行新版本实机行走验收。

游戏地面引导是路线来源，不是实时地面或水深证据。实机验收需确认该水段不再因水域轮廓触发 no_path，仍按当前引导行进；墙体、失焦与手动停止保护单独保留。离线测试不能当作整条涉水路线已实机通过。
