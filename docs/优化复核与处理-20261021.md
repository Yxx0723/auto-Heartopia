## 核对结论

用户提供的清单指出了真实问题：旧执行链与当前产品混放、缺少 CI、测试收集加载旧配置/图片库、点位锁绑定 Windows，以及协作说明仍描述星铁。

但入口导入图的不可达节点不能等同于可删除模块：它包含包标记、独立工具，也不证明函数级可达性或覆盖动态装载。本轮 AST 扫描包含所有 utils/tools/webui Python 文件和两个旧入口，得到 72 个静态可达节点、69 个不可达节点（不可达文件计 10,872 行）；该统计口径与清单不同，不能据此宣称原报告错误或所有节点都是死代码。

`tools/build_ore_route.py` 是独立维护工具，保留。`core/schema.py`、`core/json_io.py` 仍由当前 personal_route 录制数据使用，保留其实现和有效契约。旧地图校验/格式化命令仅服务旧星铁执行链，随之归档，未加入当前 CI。

直接导入次数不是依赖删除依据：若保留 PyAutoGUI，就仍须保留它需要的传递依赖。本轮先确认当前产品无需 PyAutoGUI，再从已验证环境的元数据计算运行、测试、构建依赖闭包。
