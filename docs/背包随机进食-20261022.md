# 背包随机进食与搜索等待修复

进食触发值仍是实际体力低于30。触发后读取本地 `BagModule → BackPackSystem → StorageBackpack.items`，只读取随身背包，排除仓库、零数量、锁定、停用和没有 `BackpackItemFunction.Eat` 的物品。名称去重后随机排列候选，不再按固定水果顺序盲搜；每次食用前重新查询数量。相同物品存在锁定变体时跳过该名称，避免搜索把锁定堆叠排在前面。

2026-10-22 的只读实测确认15种可食用名称，包括四种水果、菌类、海菜、大厨特制沙拉和温泉蛋；名字来自当前游戏 `TableBagitem`，不是根据图标英文名猜译。缓存只保存名字，数量和食用动作每次重新读。遇到新ID时分批只读核对名称，每批最多1秒/128MiB，支持F6/F9中断；未确认前不点击食用。

旧报错在14:48:56的日志中为 `food_paused`，文字是“背包搜索框未确认，未输入文字”。修复包括：搜索点击前先移动鼠标并等待游戏处理到位；搜索框最多等待20帧、连续两帧稳定才输入；结果同样等待完整背包标题与结束搜索按钮出现；输入后只读核对背包实际 `searchingText` 必须等于所选名称，再选择结果。未确认仍禁止输入或食用。

水果保留图标核对，其他食物使用筛选结果中的选中格子边框、真实“食用”文字、按钮颜色及相对位置联合核对。食谱的学习按钮不能通过该核对。每次只点一次，等待体力增加与动画结束后再继续；达到**数值100或以上**即关闭背包，不再追逐高于100的临时上限。

搜索、物品、体力、关闭背包等确认失败时释放输入，按1/2/4/5秒间隔自动重试；F6主动暂停、切出游戏的前台保护及F9停止继续有效。新版CLI `--check-food-output` 仅输出只读背包核对结果，不发游戏输入，供核对打包模块与源码一致。

验证包含当前进程真实只读背包、搜索/详情截图在778/1024/1366/1920宽度下的识别、库存筛选与变化保护、随机选择、延迟搜索框、错误查询拒绝、通用食物食用按钮、自动重试、单次消耗及100阈值。实机自动点击和进食结果须由用户开始回放后继续核对，不能由只读库存测试替代。

公开前置对照通过代理访问 [.NET Dictionary 实现](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Collections/Generic/Dictionary.cs) 与 [Microsoft VirtualQueryEx 文档](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex)。实际布局与数值使用当前版本运行时元数据及真实读取核对；不修改游戏内存，不调用游戏函数。


## 成品料理优先

优先使用背包实际物品类型为料理的食物，先吃最低星级（0星、1星、2星依次递增），同星级内随机选择。每口进食重新读取库存；低星料理吃完后才升至下一星级。搜索同名料理后逐格核对详情中的星级，两次画面一致且等于目标星级才返回食用按钮，避免按搜索格子顺序误吃高星料理。星级未确认时自动重试，不退到高星料理或原料。没有可用料理（例如已吃完、全部锁定）时才选择其他可食用食物。料理仍在库存但搜索或按钮未确认时自动重试，不会因此直接消耗原料。当前只读核对的温泉蛋、大厨特制沙拉均属于料理类型45；水果类型25，菌类类型97。每次进食重新查库存，体力达到100后继续路线的规则不变。
