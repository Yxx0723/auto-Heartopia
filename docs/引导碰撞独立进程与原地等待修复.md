# 引导碰撞独立进程与原地等待修复

日期：2026-10-28。基线：`a49c372`。本次针对实际窗口回放的快照过期，不修改路线、点位、走法记忆、A* 或碰撞几何规则。

## 证据与选择

15:35 回放的 5 批扫描均完整、无未知碰撞、无重试，但耗时 7.45～8.67 秒，发布即超过 6 秒有效期。导航需求窗口可用率 0%，未记录到移动键。上一轮集合恢复没有在该轮触发。

只读 py-spy 非阻塞 GIL 采样在当前窗口进程中看到了主线程地图几何筛选、显示场景读取和缓存处理。采样得到 310 个样本并报告 248 个错误，不能据此计算精确 CPU 占比，也不能单靠该采样认定唯一根因。独立读取较快、同进程回放较慢，加上这些热点，支持优先验证进程隔离。

## 实现范围

- `NavigationProcessScene` 保留 `MemorySceneMap` 的工厂/快照/关闭接口，内部使用 Windows spawn 独立进程。
- 子进程只构造既有 `NavigationSceneMap`，只读游戏；不创建窗口、输入设备或回放控制器。
- 每次请求只有一个完整响应。私有 pipe 带请求序号和游戏 PID；不接受旧响应、错 PID、错误结构或超限消息。
- 完整快照保持原始坐标、几何和观察时间；父进程继续使用原 `SceneMapWorker`、完整性及新鲜度检查，不把收到消息的时间当作观察时间。
- 子进程异常仍按原 mutation/unknown/I/O/场景变化语义处理，不退回同进程慢读取，不发布部分碰撞继续走。
- 新增子进程读取耗时、请求总耗时、消息字节数及工作进程 PID，便于区分读取和传输/父进程等待。
- 默认游戏引导使用独立进程；普通回放、地图显示和测试注入的其他工厂保持原路径。
- 关闭时先停止子进程；阻塞时仅终止本任务持有的采样进程。游戏进程从不作为终止目标。工作线程关闭增加 interrupt 钩子，避免卡在 IPC 收取时遗留采样子进程。
- EXE 入口在 GUI 导入前执行 `multiprocessing.freeze_support()`，避免冻结包子进程重复打开窗口。

## 资源与时间边界

新增阈值集中在 thresholds：单请求 8 秒、轮询 0.02 秒、关闭等待 0.3 秒、消息上限 64 MiB。这些是工程保护值，不是游戏能力实测值，也不延长碰撞 6 秒有效期。单次 OS/IPC 调用不承诺硬实时；主控制循环不等待子进程结果。

父子均使用系统单调时钟；不将引导 perf_counter 时间戳直接与碰撞 monotonic 时间戳比较。PID/场景切换继续清空旧快照；新子进程不继承旧读取器或对象缓存。
