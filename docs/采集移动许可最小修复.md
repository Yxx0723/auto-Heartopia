# 采集移动许可最小修复

适用入口：`CollectionFollower`，不改变单独游戏引导的控制流程。

## 修复

1. 区分控制周期剩余等待时间与移动许可剩余时间。正常等待不足 10 ms 不释放输入；许可剩余不超过看门狗轮询时间时仍释放。
2. 等待周期为下一次核对预留时间，参考当前周期工作时间，最多预留一个 50 ms 控制周期；最短让出 1 ms，避免忙循环。不得修改坐标观测时间、150 ms 期限或碰撞有效期。
3. `map_build` / `path_search` 回调仅在现有正常移动输入仍被许可时允许继续计算。场景身份、地形版本、几何签名、参考版本、风险版本及碰撞截面高度须与批准移动时一致。缺失地图或上下文变化立即释放。
4. 计算期间不得续期或设置新方向。原截止时间到达时，由独立看门狗释放。计算结果仍经原有路径及转向碰撞检查后，才能批准下一段输入。
5. 现有事件新增少量诊断：坐标/方向读取阶段、实际周期睡眠、按键批准后的剩余许可。读取本身不续期。

## 范围与边界

没有新增后台计算线程，没有共享可变导航地图的并发修改，也没有改写路径规划。计算很慢、碰撞快照断供或安全路径耗尽时仍可能停止；本改动不保证消除全部许可到期。

## 验证

- 45 ms 工作加 5 ms 正常等待不再松键。
- 临近截止时间提前进入下一次核对；成功续期不重复发送相同方向的按下事件。
- 建图/搜索可延续原许可，超过原期限仍由看门狗释放。
- 几何、世界、高度、风险、参考版本变化或地图缺失仍释放。
- F9、暂停、失焦、窗口尺寸变化、碰撞过期以及动作切换继续保留原测试。

实机须在新版运行后再对比 `lease_expired`、`cycle_budget_exhausted`、建图/搜索松键与完成点数。离线测试通过不能代替实机收益结论。
