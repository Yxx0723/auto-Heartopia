# 导航换入口与防重复校准实施计划

版本：审阅稿 v1.0

日期：2026-10-23

状态：用户已批准实施，本轮离线实现与验收情况见[实施记录](导航换入口与防重复校准实施记录.md)；实机验证待另行确认。

## 1. 要解决什么

让程序在同一个位置反复受阻时，能够区分：

- 当前接近方向有问题，需要换一条进入通道。
- 角色沿障碍侧滑，不能拿这段位移更新方向基准。
- 镜头方向可能变化，需要在可靠条件下核对方向。
- 坐标、场景或高度状态不明确，需要等待有效证据。

目标是减少重复撞点、原地校准和无效绕圈，不承诺任意地形都能自动通过，也不把未知区域补成可走地面。

## 2. 当前代码基线和已知事实

当前分支为 `restore/d50087c-20261023`，HEAD 为 `748d9fc`。它基于回退版本 `d50087c`，已加入周边20游戏单位的模型及碰撞细节显示。

工作区还包含上一轮新增的回放记录功能及其测试，尚未提交。实施前必须保留这些改动，不能只检出 HEAD 后开发，也不能恢复其他分支的整套实现覆盖当前版本。

当前没有启用此前 P1/P2 的稳定支撑面身份和统一地面连接评估器。本文不能以这些能力已经存在为前提。

| 现有实现 | 实际行为 | 主要限制 |
|---|---|---|
| `LocalNavigator.blocked()` | 在朝局部目标约1单位处加入半径约0.45单位的临时障碍，有效期20秒，并重新规划 | 没有方向、支撑面和移动方式隔离；临时障碍不是实测墙体 |
| `_Follower.calibrate()` | 通过 W/S/D/A 短距离移动建立方向基准 | 墙边、树旁、坡面可能影响探测位移 |
| 行走中的方向更新 | 实际与预期走廊均未被已知地图阻挡时，尝试从位移修正基准；大幅偏差触发重新校准 | 地图缺失墙体时，这道保护仍可能失效 |
| `rotate_basis()` | 方向差超过50°时拒绝更新 | 该值是现有配置，不是本次确认的游戏实测能力 |
| 回放记录 | 保存路线快照、实际轨迹、规划路径和异常现场 | 旧记录缺少的数据无法事后补造；碰撞候选不等于真实接触 |
| 走法记忆 | 保留成功走法，按估计耗时和遇阻情况选取 | 不会凭失败记录自动生成一条已经验证的通路 |

上述1单位、0.45单位、20秒、50°均是当前代码值，不应直接视为新方案的推荐参数。

## 3. 方案一：入口失败后，换接近通道

### 3.1 记录一次失败尝试，而不是画出一堵墙

新增独立的运行期尝试记录，建议包含：

| 字段 | 用途 |
|---|---|
| `attempt_id` | 区分独立尝试，避免同一段持续按键被重复累计 |
| `scope` | 绑定当前场景会话和相关局部几何状态 |
| `start / local_target / collection_target` | 分开实际起点、当前导航段目标和原采集点 |
| `direction_xz / input_keys` | 记录接近方向和尝试按键 |
| `movement_mode` | 隔离普通行走、跳跃和其他移动方式 |
| `support_ref / height_observation` | 有可靠支撑身份时引用；没有时明确未知，角色Y只是观测值 |
| `result / confidence / reason` | 区分成功、停滞、未知，以及证据来源 |
| `created_at / expires_at` | 管理临时风险的生命周期 |

当前运行期的场景上下文可以用于判断会话是否变化，但PID、指针或临时对象序号不能作为跨重启的稳定支撑面身份。角色Y也不能通过固定分桶冒充楼层。

同一次尝试内的多个采样点只补充证据；释放按键、完成独立恢复并再次接近后，才可能形成另一条尝试记录。

### 3.2 先加风险代价，不直接扩成双向障碍

优先降低本次失败接近连接的优先级：

- A→B失败，不自动影响B→A。
- B→A成功，不自动删除A→B失败记录。
- 跳跃成功，不作为普通行走成功。
- 支撑面不明确时，只保留局部、短时风险，不能形成跨高度层的硬阻挡。
- 真实墙体、水域和已核实山壁继续按原有碰撞约束检查。

第一版不设计“累计失败若干次就永久封路”。反复失败可能来自同一个错误方向基准或缺失几何，重复并不必然增加真实性。

### 3.3 候选入口从哪里来

优先顺序建议为：

1. 当前环境下重新检查过的成功走法及其连接点；仅在用户已经启用走法记忆时使用该模块。
2. 已加载几何能支持检查的障碍端部、现有道路通道或局部路径分支。
3. 以后取得可靠证据的桥头、坡道入口等连接。

不能只在采集点周围均匀取几个圆点，就当作可用入口；道路参考线也不是通行证明。

候选点必须检查“当前位置→候选入口”和“候选入口→采集点”的连接。已确认阻挡的候选淘汰；证据不足的连接保持未知，不能伪装成已验证通道。

候选排序可以考虑预计耗时、绕行长度、近期同方向失败和证据质量。权重、时间窗及尝试预算需要离线测试和实机校准，本文不指定所谓实测最优值。

### 3.4 避免左右反复横跳

- 选定入口后保留本次接近意图，不因单帧评分变化立刻左右切换。
- 确认新入口失败或发现新阻挡，才切换候选。
- 检查不同候选是否最终又落到同一个失败接近段，避免“换了名字但走法没换”。
- 保留当前按局部导航段评估进展的行为，不能仅因离原采集点更远就判断绕行失败。
- 候选耗尽后结束这一轮尝试，交给该点的有限重试、跳过或补采策略；不无限生成入口。

原采集点、原访问顺序及路线JSON保持不变。引导点是本次导航的临时数据。

## 4. 方案二：受阻时先核对，不立即原地重新校准

### 4.1 方向异常至少有三种解释

| 观察 | 候选解释 | 处理原则 |
|---|---|---|
| 某方向进展很少，侧向或反向仍有位移 | 局部障碍或侧滑 | 不用这段位移旋转方向基准，优先检查入口 |
| 多个可靠方向样本呈一致整体旋转 | 镜头变化的候选证据 | 核对后更新，不能仅凭一个样本确认 |
| 位移过小、跳落、坐标陈旧、场景更新 | 信息不足 | 释放按键并等待有效观测，不学习方向或硬障碍 |

地图返回“没有检测到已知障碍”，不等于真实环境中无障碍。尤其是目前未读到碰撞几何的墙体，不能因为 `motion_clear()` 返回真就断言发生了镜头旋转。

### 4.2 增加明确的状态切换

建议在现有跟随器上增加小范围状态控制：

```text
正常跟随
  → 方向异常或移动停滞
  → 释放按键、保存现场
  → 判断：障碍嫌疑 / 方向变化嫌疑 / 信息不足
      ├─ 障碍嫌疑：保留可信基准，换接近入口
      ├─ 方向变化嫌疑：取得可靠证据后核对方向
      └─ 信息不足：等待，不盲目驱动
  → 验证恢复效果后继续
```

“暂不更新基准”不等于可以无限沿旧方向走。若旧基准也已不可信，应停止主动行走；没有可靠方向和安全通道时，不能盲目后退找空地。

### 4.3 给重复校准增加空间和状态约束

记录校准发生的位置、目标、失败原因和有效样本。若在同一局部区域反复失败，应退出“立即再校准”流程，转入换入口、等待或结束当前点的本轮尝试。

允许再次校准的条件可以包括：

- 已到达另一处具备可靠观测条件的位置。
- 场景或坐标数据从异常恢复。
- 获得此前没有的、可信的方向观测。

不能只靠固定冷却时间：等待结束后仍在同一堵墙边重复W/S/D/A，问题可能完全没有变化。

### 4.4 校准与恢复动作的边界

沿用当前长按空格和局部恢复能力，但不能把跳跃、下落或侧滑期间的位移当作可靠方向样本。

若本轮需要多方向对照，必须先确认探测条件，并限制扰动。多方向一致旋转只能提供候选证据；当前没有可靠镜头朝向数据时，必须允许最终结果为未知。

每次状态转换均记录原基准、可用样本、决策原因及结果，方便复盘“为什么换入口”或“为什么再次校准”。

## 5. 分阶段实施及最小修改范围

| 阶段 | 工作 | 预计涉及模块 | 阶段出口 |
|---|---|---|---|
| A：补充分辨和复现测试 | 侧滑、镜头旋转、低位移、同处重复校准的离线场景；完善决策日志 | `coordinate_player.py`、回放记录模块及对应测试 | 能解释每次方向异常，正常直线与转向行为保持 |
| B：阻断无效校准循环 | 加入判断状态、重复位置约束和安全等待，不用可疑位移污染基准 | `coordinate_player.py`、`coordinate_route.py`、`thresholds.py` | 同处失败后切换处理方式，停止请求仍及时释放按键 |
| C：有方向的入口风险与候选选择 | 替换本次失败直接生成统一临时圆障碍的逻辑；增加尝试记录与候选入口 | `coordinate_navigation.py`，必要时新增独立的尝试记录模块 | 正反方向、移动方式及未知高度不互相误封；候选不反复回同一入口 |
| D：集成验证及实机验收准备 | 检查搜索、捷径、旧路径复用和走法记忆的接入；输出对照复盘 | 导航、跟随器、记录模块及回归测试 | 已确认障碍不被任何快捷路径绕过；离线通过后另行确认实机验证 |

当前回放记录功能的未提交成果应作为保留基线。入口风险需要独立数据结构；若发现必须修改多个搜索模块，先说明范围和原因，不顺手重写A*或引入完整NavMesh。

方向性风险如果用于选路，搜索、路径简化、前瞻捷径和旧路径复用都必须尊重同一语义。不能只给A*加代价，却让后面的直线捷径走回刚失败的入口。

## 6. 验收与风险控制

### 必须覆盖的离线测试

1. 斜墙侧滑：不因为一个偏移样本直接认定镜头旋转。
2. 真实方向变化的模拟输入：不能被永久忽略；证据不足时正确等待。
3. 同一位置连续校准失败：退出重复流程，不出现无限循环。
4. 同一次持续移动：多个采样不累计成多次独立失败。
5. A→B失败与B→A成功互不覆盖。
6. 普通行走与跳跃证据隔离；桥上、桥下身份不明时不跨层硬封。
7. 不同入口最终汇入同一失败段：识别并降低重复尝试。
8. 绕行暂时远离采集点：仍能根据当前局部段正确评估进展。
9. 真实墙、水域、山壁约束及已有合法通道保持。
10. A*、直连、简化、前瞻和旧路径复用不能绕过新的限制。
11. 场景变化、局部几何变化及有效期结束后，证据和相关缓存正确失效。
12. 暂停、停止、失焦、坐标失效或记录写入失败时，按键得到释放。
13. 路线点位和访问顺序未被修改；不会擅自启用用户关闭的走法记忆。

每阶段先增加能复现旧问题的测试，再修改实现；相关回归、完整默认测试、静态检查和适用的冻结包回归必须有实际记录。

### 性能与缓存

- 决策使用已有导航快照，不在控制循环额外扫描游戏内存。
- 对局部证据、候选数量和历史记录设置上限；具体值集中配置并注明用途与验证状态。
- 变化后的局部风险必须使相关路径缓存重新检查；无关远处几何变化不应导致每帧全量重建。
- 不在按键保持期间执行额外的耗时诊断；复用当前记录流程的释放与异常保护。
- 分开测量无异常的正常跟随、发生受阻时的诊断，以及重新规划耗时。

### 实机验证必须另行确认

建议依次核对：已知空地、已知墙边、可正常通行坡道、桥头、稀有木材第8点。保存基线和新版本的独立回放记录，对比到达情况、重复校准次数、失败入口复用次数、绕行距离和耗时。

出现持续无进展、方向无法确认、数据持续陈旧、疑似进入水域或错误高度层、停止后仍有按键保持等情况，应停止该次验证。时间窗和动作预算应在启动验证前明确，不能边试边无限加码。

离线模拟通过不代表真实游戏已经可通行；几何候选也不能作为真实支撑面或物理接触证明。

## 7. 本次交付和待审阅项

本稿最初交付时只新增文档。后续用户已确认按本方案实施；本轮实现、验证和能力边界见实施记录。实机回放和上传GitHub不包含在本轮自动执行范围内。

建议首先审阅以下三点：

1. 是否按“先限制无效校准，再做入口风险与候选选择”的顺序实施。
2. 是否接受无法确认方向或安全通道时先等待、跳过该点或结束本轮尝试，而不是无限重试。
3. 是否同意第一版只建立临时方向风险，不根据重复失败自动生成永久墙体。

本轮实施已获确认。实机验收、扩展支撑面建模及后续新增改造仍需明确范围后进行。
