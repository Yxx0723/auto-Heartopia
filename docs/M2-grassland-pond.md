# M2 草原湖水面显示补全

2026-11-24，基线 `31c193e`。

## 定位及来源

Windows 实机只读采样得到角色 XYZ `(-179.288834, 19.887001, -15.432209)`，水平朝向约 `(-1.0000, -0.0041)`。向西对应主场景 `startown` 的草原湖。游戏窗口实景可见池塘、南侧瀑布和对岸木板。程序地图在 `810×587`、每单位 10 像素、以角色坐标为中心的视野内，修改前的轮廓完整可见，其西北和南侧缺口来自底图数据。

- 游戏配置 `TriggerAssets.triggers` 的 `triggerId=237` 名为「草原湖」，有 198 个世界 XYZ 点，俯视投影为一块连续水域。`2370` 名为「草原湖畔」，包含外围范围且原始轮廓自交，未作为岸线数据。
- 只读核对 `sm_water_lake04_1_LOD0` 和 `sm_water_lake04_1_LOD1` 的 MeshFilter 归属、当前实例 ID、顶点/索引缓冲、局部边界及世界变换。对应 83 顶点/120 三角面和 48 顶点/44 三角面。两套网格的三角形投影各形成一个连通水面，均无岛洞。
- 游戏地图参照为既有 `memory-map/map-open-clean.jpg`，1026×800，SHA-256 `9e562c2134dd90a9d331b879df5a44ec2a7e5cc24d6f50403245beee8ed6de18`。与原始校准图 `map-open.png` 对照四个稳定地貌窗口，均得到 `(dx,dy)=(0,+7)` 像素，因此使用原点 `(511,459)` 和 `1.55` 像素/世界单位。校准原图 SHA-256 `b875f660be2adb67d7eae257ad7a86f28c21f662e59523cb268709f926954582`。

岸线以配置 237 的轮廓为基础，在两个 LOD 网格投影的交集中补入与校准图蓝色像素一致的区域。蓝色识别在四分之一像素的采样网格上使用相邻采样复核，减少地图定位误差的影响。保留与主潭连通的几何，对轮廓作 0.15 世界单位的拓扑保留简化，再裁到两份网格投影的交集。最终 51 个顶点，面积约 181.33 平方游戏单位。原轮廓面积约 104.04。主潭和南侧小潭的连接处连续，两份网格和地图参照都未确认独立小岛。

在本地参照图上，用同一高置信蓝色判据比较 422 个水面像素中心，旧轮廓覆盖 239 个，新轮廓覆盖 400 个。新轮廓内未命中同一局部窗口的高置信陆地像素中心。剩余 22 个像素集中在主潭北/西北缘和两潭连接处至南潭东缘，距新轮廓最远约 0.65 世界单位。该窄边带低于或接近地图定位精度，细节待核实。此统计衡量参照图的一致性，无法替代逐点实测岸线。

## 修改和验证

- `utils/core/map_water_reference.py` 用已核验的数据替换草原湖轮廓。
- `utils/ui/map_draw_cache.py` 和 `utils/ui/native_coordinate_monitor.py` 仅在 `startown` 主地图启用该池塘条目，离开主场景或隐藏水域时通过原有缓存隐藏，返回后重新显示。颜色、边线样式及其余水域数据维持原有配置。
- `tests/unit/test_map_water_reference.py` 覆盖两潭和窄连接处、周边陆地、闭合与无自交、缩放/平移/调整窗口、切换场景和缓存复用。

Windows 上水域、地图缓存、坐标窗口、导航水域和住宅图层共 145 项测试通过。另比较修改前后实际的 `NAVIGATION_WATER_AREAS` 序列，两者完全相同。`utils/core/navigation_water.py`、所有岛屿轮廓和其余水域条目逐项相同。

Windows 实机前后图使用同一实时场景快照、角色坐标、视野和显示设置。覆盖场景退出/返回、图层关闭/恢复、缩放和窗口调整。截图中的绿色圆点是本次只读采样的角色位置。
