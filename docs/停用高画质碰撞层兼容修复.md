# 停用高画质碰撞层兼容修复

## 问题与证据

2026-10-26 黑松露回放在第 2 点持续等待场景数据。使用部署版本读取源码独立只读采样 5 次，实体可读，但原生碰撞均报“原生碰撞图层归属已变化”。进一步检查显示：普通 SceneColliderLoader 正常；QualityHighColliderLoader.current=0，继承的 data=null，63 条 loaded 记录的 obj 全为 null；池对象存在，但 _instBoxCols 和池 _root 均未初始化。加载器自己的 _root 与配置 parent 匹配。loaded 条目数量不能视作实际加载网格数量。

旧实现对普通及高画质加载器执行同一 data 相等检查，在核对启用/空载状态前就放弃了整份原生结果。worker 因 world_state=unavailable 拒绝提供导航快照，循环重读无法改变这个稳定状态。

## 最小修复

- 对固定版本中的精确 QualityHighColliderLoader / ColliderQualityLoader 类型关系，核对 current 布尔字段及范围。
- 关闭图层仅在 loader.data=null、配置在当前根内、配置数据类型有效、加载器 parent 正确、所有 LoadRecord.obj=null、没有任何非空箱体槽时，认定没有当前可提供的箱体几何。
- 未初始化池允许 root=null，但必须同时无箱体列表；非空的错误根仍拒绝。已初始化的空列表必须有正确父级。
- 停用层的全部引用、容器戳及记录重新核验后才能发布；启用层依旧读取实际碰撞，最后再次检查启用标记。
- 增加根 configs 引用和成员集合的末尾校验。任何换根、配置、池、记录或启用切换都拒绝本轮，不保留半份结果。
- 保留普通墙体、护栏、触发器过滤、源几何/实际池槽、边界值及缓存提交保护。

改动没有将未知错误改成成功，也没有为启用且 data=null 的图层增加兜底数据源。其他未核实状态继续保守拒绝。
