# 混合采集寻路实施记录

日期：2026-11-04。基线：543185f（每次寻路档案和实走短段记忆库）。

## 实现

普通保存点位的采集入口默认关闭原生地图设标模式，直接使用 CollectionNavigator / CollectionFollower。独立“跟随游戏引导”入口保留。采集后台碰撞工作线程继续创建并供数，导航不再依赖显示用地图快照；F6、F9、独立按键许可和失焦保护继续生效。

优先完整成功走法，再使用共享实走短段，没有合适记录时使用现有局部规划。共享短段只按精确首尾位置衔接；前瞻最大 3 单位、最多 16 段，弯曲偏差不超过 0.35，且当前到前瞻点必须通过实时碰撞与风险检查。小于 1 单位且远离最终目标的零碎片段退回正常规划，防止把连续输入变回追赶采样点。使用短段时继续收集完整走法的实际轨迹与有效行走耗时。

完整旧轨迹优先选择最近可达入口，最近入口被挡才检查其他入口；不因后方入口的预计剩余成本较低就剪掉历史绕行。受阻时暂时排除当前位置及已走过的轨迹前缀，随后每秒最多重试一次前方接回。排除持续 120 秒，当前场景作用域真正改变时清除；短暂缺数据不会清空同场景排除。接入高度差使用不大于 0.35 的保守过滤，再执行当前碰撞检查。以上不是稳定支撑面 ID 或真实地面连续性证明。

每点保留原有有效行走预算和接近尝试限制；重规划、局部脱困和走法替换不重置预算。新增反复返回检测：12 秒以上的有效移动观察、至少四次回到附近且累计移动至少 6 单位，结束该次尝试并记为未完成。普通直线慢走和单纯原地等待不能仅凭该检测判为绕圈。

场景数据持续不可用满 30 秒时暂缓该点，注明数据原因，不生成墙体证据；暂停后重新开始等待计时。暂停、进食、维修、规划和采集等待仍不计入有效行走预算。

## 有限补采

普通点位每轮按原顺序先执行主流程，失败点单独排队。主流程结束后仅补采一轮，每个失败点最多再尝试一次；补采过程中失败不会重新入队。补采有单独的一次点位预算，预算不能通过局部重规划无限刷新。成功后移除该点未完成标记；全部补齐才报告完成，仍失败则保留部分完成及具体原因。循环任务每轮都有独立补采队列，已完成点不会因补采重复执行。

特殊动态资源任务及房门巡查不使用这次普通点位补采队列。保存的路线 JSON、点位顺序、各点 F 次数及等待设置不改写。到达、执行采集和确认掉落仍保留原有语义。

## 参数与边界

新增调度参数位于 utils/core/collection_schedule.py，属于工程控制与保守记录阈值，未经真实角色能力校准。真实墙体、水域、山壁及桥梁约束保留；数据不足区域仍可能无法找到可行路线。本版没有补出完整地面网格、原生 NavMesh 或可靠 grounded 标志。

短段库仍按可确认的场景会话隔离。旧完整走法兼容原格式并重新验证。旧路径可帮助规划，但不会放行当前已确认的实体碰撞。实机效果需通过短采集路线、桥头/上下层、临时障碍及停止操作逐项验收，离线模拟不等于游戏中已验证。

现有地形实验的未提交修改保留在工作区；打包候选与提交仅纳入本次采集入口及调度的改动，没有混入这些实验。
