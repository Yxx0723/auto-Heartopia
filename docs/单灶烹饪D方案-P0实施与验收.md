## 新增离线入口流程

文件：`utils/flows/cooking_entry.py`，未连接正式界面，也不创建游戏读取器、窗口或输入设备。

调用者显式提供窗口、控制、输入、只读食谱/面板/背包回调、输入互斥、时钟和持久记录路径。测试全部使用替身。

1. 验证接口、任务归属和旧记录；不完整或不同归属的旧记录不能授权重发。
2. 领取已有 InputTaskGate；其他任务占用时不读取、不发送输入，也不释放其他任务的按键。
3. 确认前台、窗口尺寸和 F6/F9 状态。
4. 独立读取面板状态与食谱归属。未知不发送输入，归属不一致停止。
5. 面板已打开则不发送数字 1。面板关闭时，必须有调用者的人工就位确认。
6. 先原子保存 ENTRY_DISPATCHED，再发送一次主键 1 并释放。异常、停止或重启后均不盲目重发。
7. 面板打开后复用 bind_default_recipe 核对实际槽位、材料归属、可用份数和保留量。只读取，不选菜、不替料。
8. 两次新读取的一致结果才进入 RECIPE_VALIDATED，保存食谱/材料/背包证据，立即结束。started_pots 永远为 0。

`read_menu` 的约定为 `{state: 'ready', open: bool, scope: str}`。它必须由经验证的只读面板状态生产者提供，不能用 `selected != None` 或一个猜测字段实现。初次离线阶段未提供真实适配器；后续新增 CookingMenuStateReader，依据已读取的实际对象与字段进行核对，不猜测状态。

入口采用有界等待，时间只用于超时和释放，不代表烹饪事件。P0 无开始、翻锅、收菜分支。

## 测试结果

专项：86 项通过，包括原有烹饪专项 66 项及新增 P0 测试 20 项。

新增覆盖：主键区 VK_1、已开面板不重复交互、缓存食谱不能授权输入、人工就位要求、入口无反馈不重发、持久记录恢复、输入异常、跨场景归属、读取暂时失败、锁定/星级/空槽/材料不足、任务互斥、F6/F9/失焦/尺寸变化释放、证据深拷贝。任何测试都未打开真实游戏句柄或发送真实输入。

完整回归：`python -m pytest tests/unit -o addopts= -q --tb=short`，2322 项通过、1 项失败，耗时 203.19 秒。失败为原有 `test_traversal_memory.py::test_failed_run_keeps_successful_partial_motion_and_all_archive_sources`，其 `read_text()` 未指定编码，Windows 默认 GBK 无法读取 UTF-8 learning.json。该测试及相关生产文件与 HEAD 无差异；本轮未修改。

使用 `python -X utf8 -m pytest tests/unit/test_traversal_memory.py::test_failed_run_keeps_successful_partial_motion_and_all_archive_sources -o addopts= -q --tb=short` 单独复验通过（0.25 秒）。这是编码环境的定点验证，不将其改称“默认环境完整回归全部通过”。没有修改全局编码或测试文件来掩盖失败。

新增文件 pyflakes 和 git diff --check 通过。不能用专项通过替代完整回归，也不能把离线键值验证写成真实灶台打开成功。
