# 导航停滞监控与重复入口修复

日期：2026-10-27。基线提交：`8fad07c`。本次仅离线开发、验证与构建，不操作游戏、不部署或重启当前程序。

## 问题与复现

原有回放已有 2 秒无进展检测，但临时转向点每次变化会重设 `best/progress_at`；因此实际角色不动、临时点不断变化时可以一直逃过检测。场景短暂未就绪时 `_refresh_obstacles()` 又会清除刚记录的失败方向风险。连续恢复流程还会在同一次卡障的每次尝试中重复大跳。

先新增离线行为测试，确认上述 3 项在修改前失败。随后扩展为 12 个专项用例，涵盖坐标目标抖动、场景缺失/上下文为空/真实场景切换、证据过期、旧路径复用、量化短按、上下层和方向/移动方式隔离、有效时间及跳过后继续采集。

## 最小改造

1. 新增纯逻辑 `NavigationProgress`，按 `(轮次, 点位)` 绑定，独立观察实际 XZ 位移。临时目标变更不刷新该观察窗；原地跳跃的 Y 变化不算水平进展。它与原有沿路径进展判断并行，合法绕路仍可执行。
2. 单点累计有效执行预算，不随重新规划、局部脱困或改变临时目标更新。按初始水平距离和已获得的速度估计计算 `min(600, 60 + 3 × 初始距离/速度)` 秒；速度仅用于预算，并限制为 0.5～10 单位/秒。所有值都是工程初始保护参数，未声称为游戏实测能力。规划、场景等待、菜单维护、暂停、采集等待不计入本项预算。
3. 对启用导航的持续恢复，同一次未解决卡障首次尝试大跳；后续改为原有后退、交替侧移、扩大侧移和重新规划。真正恢复进展后，新的卡障事件仍可优先跳跃。原有非导航回放的恢复策略保留。
4. 临时场景缺失只失效路径和碰撞图，不立即清除短期风险，也不使用旧路径继续走。风险仍按 TTL 过期；明确的新场景上下文会清理旧证据，ready 快照返回后仍做范围和几何复核。
5. 两次独立失败仍重合的局部接近走廊，会暂时拒绝相同入口；单次失败仍是风险代价。最终导航转向点、旧路径复用，以及实际量化 WASD 短按均检查重复入口。该限制关联方向、高度范围、移动方式和有效期，不生成永久物理墙，不影响反向或明显不同的侧向接近。
6. 沿用现有单点尝试次数限制，另以单点时间预算兜底。超过后释放按键，标记本点未完成并继续后续点；日志记录原因、有效时间和预算。本轮包含跳过机制，没有新增单独的尾部补采队列；后续循环仍遵守用户原有循环配置，不能称为已完成有限尾部补采调度。

不修改真实墙体、水域、山壁或桥梁的硬约束；不新增方向走动校准，不切换走法记忆开关，不改用户路线文件，也没有把全图源碰撞候选直接铺成导航硬墙。

## 验收边界与后续

本次证明的是离线模拟中：目标抖动不能隐藏静止角色、短暂读取失败不丢失同场景风险、已重复失败的同一入口会被拒绝、点位超预算可跳过并继续采集下一点。不能据此声称真实山壁、护栏、大跳或桥梁已实机验证。

场景长期不可用、持续等待目标高度恢复、实际输入未生效等仍是独立问题；不会为了避免等待而使用过期碰撞数据盲走。该预算也不等价于墙钟总时长。单点大范围来回移动可被总预算兜底，但尚无完整的环路轨迹识别器。下一步先用实际回放核对 `movement_stall`、`physical_stall`、`point_drive_seconds` 和 `point_skipped`，然后再分层接入已核对的全图碰撞形状与补采调度。
