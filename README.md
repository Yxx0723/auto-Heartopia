# auto-Heartopia

《心动小镇》Windows 原生坐标观测与路线回放工具。实时只读本地角色坐标，添加采集点，按顺序行走和按 F 采集；使用独立窗口，无需浏览器。

## 当前功能

- 原生深色窗口，右侧 XYZ 横向显示；地图以红色角色标记居中，滚轮缩放，分类列表浮动展开。
- 固定树木、蓝莓、树莓、普通灌木、岩石、矿石使用配置与缓存显示；昆虫、蝴蝶、鸟、鱼等跟随当前加载对象更新。资源位置不等于当前可采集状态。
- 地图叠加水域、道路参考、围栏和已核对山壁；静态绘图缓存复用。后台碰撞范围默认 150 单位，范围控件和统计信息已隐藏，不修改游戏加载距离。
- 多条命名路线；添加当前点位、删除指定点位、逐点等待、清空当前路线、改名和另存为。清空/删除保留备份。
- 起点方式可选按保存顺序（完整回放）或最近点接入，默认最近点接入（最近点 → 末点），1～999 轮循环。局部自动寻路结合实际障碍与参考水域；遇阻先大跳，再尝试后退和左右绕行，默认每轮 5 次并可持续重试。
- 大障碍绕行采用局部搜索与大范围引导结合：优先完整局部路段，必要时用已知障碍规划较远绕路，再逐段核对当前场景；支持粗细网格与任意角连线。计算预算、部分路径和无路结果分开处理，避免把计算超时当成需要跳跃。检索与对照见 [寻路优化记录](docs/寻路优化与检索-20261021.md)。
- 点击「优化另存」按当前位置和循环次数优化访问顺序，保留原路线。普通点位回放稳定绕行优先，失败点延后、最多补采两轮，结束列出未完成点。来源、预算与模拟见 [采集路线优化与补采](docs/采集路线优化与补采-20261021.md)。
- 走法记忆当前已禁用并从界面隐藏；旧记忆文件保留，不参与当前窗口回放。
- 回放时检查斧镐；手持工具显示实际耐久，低于 20% 可自动用普通维修盒。体力数值低于 30 可从背包搜索普通水果，核对恢复并关闭面板后继续。
- 溜溜橡木、无暇萤石支持自动巡查与到点确认；默认连续按 F 3 次。位置线索只能用于接近，确认实际对象和采集状态后才交互；未找到不会当成全图没有。
- 记录回放结果、各次完成时间及过程数据。F6 开始/暂停/继续，F9 停止；失焦暂停，退出释放按键。
- 附着载具时仍可显示经校验的载具根实体位置；自动脚步回放需先下车。

仓库不附带预设采集路线。个人路线、缓存、日志和回放记录保存在 EXE 旁，并排除在 Git 跟踪范围之外。

## 源码运行

游戏控制支持 Windows 10/11、64 位 Python 3.12。手动打开游戏并进入角色，再启动工具；读取游戏可能需要管理员权限。

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
.venv/Scripts/python.exe tools/coordinate_monitor.py
```

也可运行 `Start-Heartopia.bat`。运行时配置和识别图在 `resources/monitor/`，独立维护脚本 `tools/build_ore_route.py` 继续保留。

原生入口负责会话与生命周期，布局、绘制、路线操作分别在 `utils/ui/monitor_*.py`；回放的采集、脱困和补给执行在 `utils/flows/playback_*.py`。职责类共用一个会话状态，拆分记录及验证见 [P1 结构拆分](docs/结构拆分与验证-20261021.md)。

`requirements.txt` 是运行依赖，`requirements-dev.txt` 额外声明测试和构建工具；`requirements-lock.txt` 锁定当前已验证的完整依赖集合。Windows 专用包带平台标记。

## 验证与打包

```powershell
.venv/Scripts/python.exe -m pytest -o addopts= -q
.venv/Scripts/python.exe -m PyInstaller --noconfirm packaging/HeartopiaMonitor.spec
```

直接运行 pytest 默认包含 `tests/` 和 `personal_tests/`。测试使用替身、真实识别样本或临时文件，不操作游戏。非 Windows 平台只测试离线逻辑，原生输入/窗口契约明确跳过。跨平台测试支持不等于游戏控制支持其他系统。

`.github/workflows/run.yml` 对 push、pull request 和手动触发配置 Windows / Ubuntu / macOS 离线回归，并在 Windows 构建 EXE。工作流是否通过以 GitHub 实际运行结果为准；本机结果和迁移记录见 [本轮优化复核](docs/优化复核与处理-20261021.md)。

构建输出 `dist/HeartopiaMonitor.exe`，包含管理员权限清单和当前所需图片/版本配置，不包含游戏文件、个人路线或 legacy 档案。

## 使用与限制

在采集位置添加点位，设置路线、起点、循环次数与等待，点击“按顺序回放”，切回游戏按 F6。校准时需要空旷平地。详细操作见 [使用说明](docs/使用说明.md)。

坐标读取按游戏模块指纹与对象归属校验，未知版本拒绝使用旧布局。换场景验证尚未完成，失效时需要重新定位或更新配置。动态对象受游戏加载/同步范围限制，显示缓存不能证明远处资源当天仍在。

自动寻路没有完整游戏导航网格；参考水域可能误挡桥，复杂山路、坡面和跨层通路仍需实际核对。普通点位 F 后等待仍是定时等待；动态资源状态检查也不能保证每次输入都实际掉落。完整实机巡查和采集效果需另外验证。避障依据见 [障碍处理与参考资料](docs/障碍处理与参考资料.md)。
